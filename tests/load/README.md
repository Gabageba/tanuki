# Нагрузочный тест сервера

Тест поднимает отдельный Docker Compose project с временной базой, 200 пользователями
и настоящими сессиями. Порты не публикуются, сеть `internal`, рабочие данные не используются.
В `finally` удаляются только контейнеры, сеть и тома созданного проекта.

Нужны Node.js 24+, локальный Docker с Unix socket и заранее собранные образы:

```sh
docker build -t tanuki-api:local -f apps/api/Dockerfile .
docker build -t tanuki-web:local -f apps/web/Dockerfile .
pnpm --filter @tanuki/api build
node tests/load/run.mjs
```

API запускается из текущего `apps/api/dist` с зависимостями готового production-образа.
После изменения зависимостей образ тоже нужно пересобрать. Runner не скачивает образы:
`postgres:17.6-alpine` и `valkey/valkey:8.1.3-alpine` должны быть доступны локально.
Имена API/web-образов переопределяются через `LOAD_API_IMAGE` и `LOAD_WEB_IMAGE`.

Прогон сравнивает два бюджета без swap:

| Профиль VPS |      API | PostgreSQL | Valkey: счётчики | Valkey: кеш |   Caddy | Запас для ОС |
| ----------- | -------: | ---------: | ---------------: | ----------: | ------: | -----------: |
| 1 ГиБ       |  416 МиБ |    160 МиБ |           32 МиБ |      64 МиБ |  96 МиБ |      256 МиБ |
| 2 ГиБ       | 1216 МиБ |    192 МиБ |           64 МиБ |      64 МиБ | 128 МиБ |      384 МиБ |

Пять сервисов закреплены за одним и тем же CPU (`cpuset: 0`), без разделения ядра на
фиксированные квоты между сервисами. Генератор запросов закреплён за CPU 2–3, локальный источник —
за CPU 1: нужен Docker с минимум четырьмя CPU. Они находятся за пределами бюджета приложения.
Caddy получает `GOMEMLIMIT` в 75% своего лимита. Это имитация ограничений ресурсов, а не
полноценная виртуальная машина с собственной ОС. Лимиты памяти заданы по контейнерам:
свободную память другого контейнера процесс занять не может.

Сценарии последовательно повышают число одновременных запросов без пауз между ними:

- `mixed`: авторизованные чтения каталога, тайтла, списка глав, страниц, настроек и прогресса;
  каждый восьмой запрос сохраняет прогресс в PostgreSQL;
- `pages`: проксирование JPEG-страниц 1600 × 2400, примерно 2,6 МиБ каждая;
- `covers`: разные URL без попаданий в кеш, JPEG → WebP шириной 480;
- `login`: проверка настоящего Argon2-пароля и создание серверных сессий.

Используется настоящий HTML-парсер AComics. Исходный JPEG создаётся из случайного шума,
поэтому плохо сжимается. Источник отвечает с задержкой 50 мс; скорость сети не ограничивается.
Подмена источника и разрешение его внутреннего адреса существуют только в тестовом preload,
production-код защиты URL не меняется.

По умолчанию ступень длится 12 секунд. При ошибках, p95 выше 3 секунд или остановке любого
сервиса дальнейшее повышение в этом сценарии прекращается. Между сценариями сервисы
перезапускаются, кеш очищается; пользователи и прогресс остаются в БД до конца профиля.
Все HTTP-статусы, включая ожидаемые 429 от защиты входа, сохраняются отдельно; их нельзя
выдавать за успешные запросы или падение сервера. Таймаут запроса — 5 секунд.

```sh
LOAD_PROFILES=1 LOAD_SECONDS=60 node tests/load/run.mjs
```

Для длительной проверки выбранной ступени:

```sh
LOAD_PROFILES=1 LOAD_SECONDS=60 LOAD_SCENARIOS='[["pages",[50]]]' node tests/load/run.mjs
```

Третий элемент сценария может задать длительность одной ступени:
`LOAD_SCENARIOS='[["pages",[100,200]],["covers",[10],60]]'`.

Перед нагрузкой runner заполняет кеш данными сверх 32 МиБ, проверяет вытеснение и сохранение
счётчика rate limit. После перезапуска API проверяет удаление только старого namespace `cache:*`.
HTTP-проверка подтверждает отказ для тела больше 16 МиБ, переполнения при распаковке gzip
и чрезмерной ширины ресайза; readiness после этих запросов должен оставаться успешным.

Отчёт — `tests/load/report/results.json`: запросы/с, p50/p95, ошибки, OOM, CPU и память.
Рабочая память контейнеров снимается раз в ~500 мс через Docker Engine API с вычетом
`inactive_file`, как в `docker stats`. Пик суммы — одновременное потребление пяти сервисов;
индивидуальные пики могут приходиться на разные моменты. Очень короткий пик может быть пропущен.

Результат зависит от CPU хоста и размеров картинок. Число одновременных запросов не равно
числу читателей. Тест не измеряет браузерную память, длительный рост кеша, реальные внешние
источники, поиск по всем источникам, резервное копирование или сборку Docker-образов.
Фоновые проверки источников и обновления закладок отключены.
