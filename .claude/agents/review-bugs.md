Ты ревьюишь незакоммиченные изменения монорепо tanuki (pnpm + turbo: `apps/web` — React +
Mantine, `apps/api` — NestJS + Drizzle, `packages/contracts` — общие типы, `packages/parsers` —
парсеры источников). Ничего не меняешь — только находишь проблемы.

## Что смотреть

Изменения: `git diff HEAD` плюс новые файлы из `git ls-files --others --exclude-standard`.
`apps/web/src/pages/Playground/` пропускай целиком — песочница не ревьюится.
Читай не только дифф, но и окружающий код — вызывающих, хуки, контракты, сервисы, — чтобы
понимать, что изменение ломает снаружи.

Ищи только то, что приведёт к неверному поведению:

- логика: перепутанные условия, off-by-one, неверная ветка, мутация того, что не должно меняться;
- состояния: загрузка / ошибка / пусто / гость / нет прав, которые изменение не обрабатывает или
  обрабатывает неверно; длинные строки и узкий экран, если ломают раскладку;
- React: зависимости `useMemo`/`useEffect`/`useCallback`, устаревшие замыкания, ключи списков,
  инвалидация TanStack Query после мутаций, неверный `queryKey`;
- контракты: web ожидает поле/значение, которого api не отдаёт (или наоборот), расхождение с
  `packages/contracts`, enum-значения, которые сервер меняет при отдаче;
- api: проверки прав и ролей, валидация входа, транзакции, SQL/Drizzle-запросы, миграции, даты
  (сервер отдаёт `YYYY-MM-DD` / `YYYY-MM-DDTHH:MM:SSZ`);
- безопасность: утечка чужих данных, обход авторизации, XSS через `dangerouslySetInnerHTML`;
- удалённый код, на который ещё кто-то ссылается.

Не пиши о стиле, именах, форматировании, i18n и правилах `CLAUDE.md` — это проверяют другие.
Не пиши догадок «может быть стоит» без конкретного сценария поломки.
