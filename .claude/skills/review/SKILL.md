# Ревью незакоммиченных изменений

Весь диалог — на русском. Охват — **всё незакоммиченное**: staged, unstaged и новые файлы.
`apps/web/src/pages/Playground/` ревьюеры не смотрят — песочница не ревьюится (линтеры по ней
всё равно проходят: их запустит хук `pre-commit`).

Typecheck и тесты здесь **не запускаются** — их гоняет хук `pre-commit`.

## 1. Охват

```bash
git status --porcelain
git diff HEAD --stat
git ls-files --others --exclude-standard
```

Изменений нет — скажи об этом и остановись. Запомни список изменённых файлов: он нужен для
шагов 2–3 и для сводки.

## 2. Механика — чинится сама

Только по изменённым и новым файлам (удалённые пропусти):

1. `*.ts`, `*.tsx` — `pnpm exec eslint --fix <файлы>` (из корня; конфиг найдётся по пакету).
2. `*.scss` — `pnpm exec stylelint --fix <файлы>`.
3. Всё, что берёт prettier (`ts`, `tsx`, `scss`, `json`, `md`, `yml`, `mjs`) —
   `pnpm exec prettier --write <файлы>`.
4. `package.json` — `pnpm exec sort-package-json <файлы>`.
5. Контроль: `pnpm lint` (eslint по пакетам, stylelint, prettier --check, `lint:i18n`).
   Ошибки, которые `--fix` не снял, разбери: если исправление однозначное — почини сам, если
   нет — в сводку как блокирующее.

Вывод `pnpm lint:i18n` сохрани целиком — он идёт ревьюеру переводов.

## 3. Ревьюеры — параллельно

Запусти **в одном сообщении** три агента через `Agent` (`run_in_background: false` у всех
трёх — дальше нужен их результат):

| `subagent_type` | Модель | Что ищет                                                 |
| --------------- | ------ | -------------------------------------------------------- |
| `review-bugs`   | opus   | баги, логику, состояния, контракты web↔api               |
| `review-rules`  | sonnet | нарушения правил `CLAUDE.md`                             |
| `review-i18n`   | haiku  | имена ключей, качество ru/en, дубли, plural, типографика |

Промпт каждому: список изменённых файлов из шага 1 (без `pages/Playground/`) и одна строка о
сути изменений (по названию ветки и диффу). Ревьюеру переводов — ещё вывод `pnpm lint:i18n`.
Если изменений в `apps/web` нет — `review-i18n` не запускай; если изменены только docs/конфиги
— не запускай `review-bugs` и `review-i18n`, `review-rules` смотрит только то, что к нему
относится (или тоже пропусти, если правилам там нечего проверять).

## 4. Проверка находок

Агенты ошибаются — особенно haiku. Каждую находку проверь сам по коду, прежде чем чинить или
показывать:

- открой место, убедись, что проблема есть именно в изменённом коде;
- для правил — что правило действительно так сказано в `CLAUDE.md` и исключение не подходит;
- для переводов — что предложенное имя/перевод соответствует правилам Localization и не
  дублирует существующий ключ.

Ложные находки отбрось молча.

## 5. Что чинить самому

Сразу, без вопросов:

- всё механическое: находки `review-rules` с «Механическое: да» и оставшиеся ошибки линтеров с
  однозначным исправлением;
- **все переводы**: отсутствующие ключи в `ru.json`/`en.json`, неточный en, переименование
  ключа по правилам (в словарях и во всех вызовах), переиспользование существующего ключа
  вместо дубля, plural-формы, неразрывные пробелы, удаление неиспользуемых ключей, которые стали
  такими из-за этих изменений; литерал в JSX → `t()` с новым ключом.

После правок — снова `pnpm lint` (в том числе `lint:i18n`). Должно быть зелёным.

Баги и немеханические нарушения правил **не чини** — только сообщи.

## 6. Сводка

```
## Ревью: <ветка>, <N> файлов

Проверки: pnpm lint — ✅ / ❌ (что упало)

### Исправлено автоматически
- path:line — что сделано

### Нужно решение
- [bug] path:line — проблема. Сценарий: … Предложение: …
- [rules/<раздел>] path:line — проблема. Предложение: …

### На заметку
- некритичное (например, предупреждения lint:i18n о старых ключах, которые изменения не
  трогали)
```

Пустые разделы не показывай. Ничего не нашлось — так и скажи одной строкой.

Пункты «Нужно решение» — **блокирующие** для `/commit`. Пункты «На заметку» коммит не
блокируют.
