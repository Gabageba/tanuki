# Playground → код: реализация выбранного варианта

Задача: `$ARGUMENTS`

Весь диалог — на русском. `CLAUDE.md` действует полностью; ниже — только то, что специфично для
переноса макета в приложение.

## 1. Найти решение

1. Найди задачу в `PLAYGROUND_TASKS` (`apps/web/src/pages/Playground/models.ts`) по пути или
   названию из аргумента. Без аргумента — возьми задачи с `decision` и спроси, какую.
2. Если `decision` не заполнен — остановись: вариант ещё не выбран. Предложи сначала
   зафиксировать его через `/playground` (шаг 7 того скилла).
3. Прочитай **источники правды**:
   - план фичи `docs/plans/<task-kebab>.md`, если он есть (от `/feature-plan`), — скоуп,
     сценарии, логика, данные и API, крайние случаи, этапы реализации. Это основа всего, что не
     про вид;
   - раздел задачи в `docs/11-ui-decisions.md` — что выбрано, почему, что отвергнуто, что
     оговорено на реализацию (баги, серверные поля, заглушки);
   - страницу песочницы — раздел «Итог», если он есть, иначе компоненты выбранных кодов. Отсюда
     берутся вид, раскладка, тексты и поведение (что меняется при каком состоянии).
4. Если они расходятся (текст на странице не тот, что в docs, поведение в «Итоге» не совпадает с
   описанием) — не выбирай сам, спроси.

Помни, что в песочнице не идёт в приложение: всё в `SandboxOnly` («Только песочница»), рамки
десктоп/телефон, моки и сгенерированные картинки, кнопки-триггеры. Это обвязка, а не решение.

## 2. Разведка реального кода

1. Найди, где фича живёт сейчас (`pages`, `entities`, `shared`), прочитай компоненты, хуки,
   `models.ts`, тексты в `shared/locales/{ru,en}.json`.
2. Данные: какие поля приходят из API (`packages/contracts`), хватает ли их варианту. Если
   варианту нужно то, чего нет (новое поле, эндпоинт, сообщение ошибки), — это часть работы, а
   не повод упростить вариант.
3. Состояния, которых в макете не было: загрузка, ошибка, пусто, нет данных, гость, длинные
   строки, узкий экран. Для каждого реши, как он выглядит, по аналогии с соседним кодом.
4. Docs по фиче, кроме `11-ui-decisions.md` (`04-api-contract`, `09-legal`, `10-header-gaps` и т.
   п.): что там устареет после реализации.

## 3. Вопросы

Спрашивай через `AskUserQuestion` только о реальных пробелах — то, что не следует ни из решения,
ни из кода: состояние, которого макет не показал и у которого нет очевидного аналога; данные,
которых нет на сервере и которые можно получить по-разному; расхождение docs и страницы. С
`(Recommended)` у того, что считаешь лучшим. Нет пробелов — не спрашивай.

## 4. План — на утверждение

Покажи план списком в чате:

- **Файлы** — что меняется, что создаётся (в каком слое и почему там — правило «рядом с
  единственным потребителем» / `shared/` из `CLAUDE.md`), что удаляется.
- **Тексты** — таблица новых ключей i18n: ключ → `ru` → `en`. Имена — по правилам
  «Localization» из `CLAUDE.md` (буквальный перевод значения, без суффиксов по месту
  использования, переиспользование существующих ключей, plural-ключи). Какие старые ключи
  уходят.
- **API и контракты** — новые поля, сообщения ошибок, проверки; какие тесты добавятся.
- **Отличия от макета**, если они вынуждены (данных нет, состояние не показывалось), — с
  причиной.
- **Docs** — что поправится.

**Код не пиши, пока пользователь не ответил «ок»** (или не поправил план — тогда покажи
исправленный).

## 5. Ветка

Новую ветку не создавай: её уже создал `/playground` от свежего master, когда собирал макеты, —
реализация продолжается там же, `feat/<задача-kebab>`. Если ты не на ней — переключись
(`git switch feat/<задача-kebab>`). Если такой ветки нет (задача старше этого правила) или в
рабочей копии есть чужие незакоммиченные изменения, не связанные с задачей, — спроси, от чего
ветвиться и что с ними делать. **Не коммить и не открывай PR**, пока пользователь не попросит.

## 6. Реализация

- **Из `pages/Playground` ничего не импортируется** — песочница только в DEV. Компоненты пишутся
  заново по образцу макета, в слое, согласованном в плане.
- Литералы макета → `t()` с ключами из плана, в `ru.json` и `en.json` разом. Удали ключи, которые
  больше нигде не используются.
- Моки → реальные данные из API/хуков; сгенерированные картинки → то, что оговорено в решении.
- Песочницу не трогай: страница остаётся артефактом решения. Если правка общего компонента
  ломает её сборку — почини импорт в песочнице, не меняя вида вариантов.
- Серверная логика меняется — тест в `apps/api` (vitest, `*.test.ts` рядом с сервисом) на новое
  поведение.

## 7. Проверка

1. `pnpm typecheck`, `pnpm lint`, `pnpm test` (или по затронутым пакетам через `--filter`). Падает
   — чини; не сдавай с красным.
2. **Саморевью по `CLAUDE.md`** — пройди по каждому изменённому файлу:
   - компоненты и хуки — `function` + `export default` в конце; хелперы — стрелочные с named
     export; `type Props`, никаких `interface`;
   - enum — const-объект `{ SCREAM_CASE: camelCase }` + `EnumLiteralsOf`, один на концепт, из
     `@tanuki/contracts`, если он там есть; хелперы по enum — `switch` без `default`;
   - Mantine вместо `div` + CSS-модуль; иконки Phosphor в `leftSection` у кнопок, полей, табов и
     пунктов меню (кроме «Отмена» в модалке); самозакрывающиеся пустые элементы;
   - цвета через `var(--mantine-color-*)` / тему; шрифт — «речь или показание»; `<Mdash />` вместо
     `'—'`;
   - i18n: ключи по правилам, фраза — одним ключом с интерполяцией, plural-формы, типографика
     сокращений с ` `;
   - даты — в серверном формате.
3. Тексты сверь с поведением: каждый заголовок и описание говорят ровно то, что делает элемент.

## 8. Docs

В разделе задачи в `docs/11-ui-decisions.md` допиши абзац `Реализовано <дата>:` — где живёт
реализация (файлы/компоненты) и чем она отличается от макета, если отличается, с причиной.
Поправь устаревшее в других docs по фиче. Если есть план `docs/plans/<task-kebab>.md` — поставь
ему статус `**Реализован** · <дата>`, отметь сделанные этапы и допиши, чем реализация отличается
от плана, если отличается (с причиной); незакрытое переедет в «Открытые вопросы».

## 9. Сдача

Коротко: ветка, что сделано (по пунктам плана), отличия от макета, что проверено — с честным
результатом команд — и что не проверено (например, вид в браузере не смотрел). Предложи
закоммитить и открыть PR — сам не делай.
