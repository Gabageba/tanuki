# 02 — Технологический стек

Все версии проверены в npm-реестре 31 июля 2026. Указан мажор, который берём.

## Поправки к первоначальному плану

Три вещи изменились с тех пор, как вы формировали список из `gabageba-ui`:

1. **Mantine уже 9.x**, а не 8. Ставим `^9.5.0` — в 9-й ветке переработаны CSS-переменные
   темы, что как раз удобно для «тёмной по умолчанию» читалки.
2. **TypeScript 7.0** — это тот самый компилятор, переписанный на Go. Сборка и `tsc
--noEmit` в CI кратно быстрее. Стоит брать сразу, но заложите пару дней в Фазе 0 на
   притирку плагинов (`typescript-eslint` работает, но проверьте свои кастомные правила).
3. **ESLint 10** требует flat config — тот же формат, что у вас уже в `gabageba-ui`, так
   что миграция минимальна.

### Почему Mantine 9

Из четырёх кандидатов он единственный не тянет за собой Tailwind. Это важно конкретно
для вас: у вас настроен Stylelint с правилами именования классов и SCSS-конвенциями из
`gabageba-ui`. С Tailwind (shadcn/HeroUI) Stylelint становится декорацией — стилей в
CSS-файлах почти не остаётся. Mantine работает на CSS Modules, поэтому весь ваш
существующий тулинг остаётся осмысленным, а `.module.scss` пишется ровно как раньше.

Плюс прикладной бонус: хуки `use-hotkeys`, `use-intersection`, `use-local-storage`,
`use-fullscreen`, `use-idle` — это буквально половина инфраструктуры читалки, не нужно
писать самому.

Что взять из Mantine, а что писать руками: **вся оболочка** (AppShell, навигация,
модалки, фильтры каталога, формы, скелетоны) — Mantine. **Сама читалка** — полностью
кастомная. Ни одна UI-библиотека не даёт готового вертикального webtoon-вьюера с
prefetch и pinch-zoom, и не надо пытаться натянуть на это Carousel.

### Отвергнутые варианты (для протокола)

- **shadcn/ui + Tailwind 4** — лучший DX и самый актуальный стек 2026, но конфликтует с
  вашим Stylelint-сетапом и требует переписывания правил линта.
- **HeroUI** — красив из коробки, но та же привязка к Tailwind плюс Framer Motion в
  зависимостях, что для читалки на слабых Android-устройствах лишний вес.
- **Ark UI / Park UI** — максимальная свобода, но для соло-разработки это лишний месяц
  на сборку того, что Mantine даёт готовым.

### Почему NestJS, а не голый Fastify

Проект по природе слоистый: источники → нормализация → кеш → API. Nest даёт этой
слоистости каркас (модули, DI, интерсепторы), а не заставляет изобретать её. Конкретная
выгода — кеширование и rate limiting навешиваются декораторами, а не руками в каждом
хендлере. Fastify под капотом сохраняет производительность для стриминга картинок.

Плата — бойлерплейт. Если через месяц окажется, что API — это шесть эндпоинтов и всё,
Nest будет выглядеть тяжеловато. Это осознанный размен в пользу роста.

## Инфраструктура

- **Valkey 8** — форк Redis под BSD. Кеш каталога и метаданных.
- **PostgreSQL 17** — аккаунты, библиотека, прогресс чтения. Нужен только с Фазы 5.
- **Docker Compose** для локальной разработки, что угодно для прода.

Парсеры источников (`packages/parsers`) — TS-библиотека в процессе `apps/api`, отдельного
рантайма для них больше нет, см. [03 — Слой парсеров](03-parsers.md).

## Структура монорепо

```
tanuki/
├── apps/
│   ├── web/                    # React + Vite PWA
│   └── api/                    # NestJS BFF, импортирует @tanuki/parsers в процесс
├── packages/
│   ├── parsers/                 # TS-парсеры 23 RU-источников (GPLv3, см. docs/09-legal.md)
│   ├── contracts/                # zod-схемы + выведенные типы, общие для web и api
│   ├── eslint-config/            # общий flat config
│   ├── stylelint-config/         # общие правила SCSS
│   └── tsconfig/                 # базовые tsconfig'и
├── docs/
├── docker-compose.yml
├── pnpm-workspace.yaml
└── turbo.json
```

`packages/contracts` — самая ценная часть монорепо. Доменная модель описывается один раз
zod-схемой, бекенд валидирует ей ответы парсеров, фронт получает выведенные типы. Рассинхрон
типов между фронтом и беком становится ошибкой компиляции, а не багом в проде.

Весь монорепо — единый pnpm-workspace, все задачи (`build`/`lint`/`typecheck`/`test`) идут через
`turbo`. Отдельных внешних систем сборки больше нет.
