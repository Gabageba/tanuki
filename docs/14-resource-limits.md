# Ограничения ресурсов

В стандартном Docker Compose кеш и защита входа используют разные процессы Valkey:

- `cache`: кеш ответов и обложек. По умолчанию `maxmemory=32mb`, `allkeys-lru`, лимит
  контейнера 64 МиБ. Старые записи вытесняются; кеш не сохраняется на диск и после
  пересоздания заполняется запросами.
- `valkey`: счётчики rate limit. Они сохраняются в прежнем томе и не участвуют
  в вытеснении кеша. Пользовательские данные остаются в PostgreSQL.

При обновлении API удаляет только старые `cache:*` из прежнего общего хранилища,
сохраняя `ratelimit:*`. Готовность API проверяет PostgreSQL и оба хранилища Valkey.
Без `CACHE_REDIS_URL` сохраняется совместимость со старой общей конфигурацией,
но ограничения отдельного кеша тогда нужно обеспечить самостоятельно. Не включайте
`allkeys-lru` в общем хранилище счётчиков и кеша.

В серверном `.env` можно изменить `CACHE_MAX_MEMORY` (по умолчанию `32mb`) и
`CACHE_MEMORY_LIMIT` (`64m`). `maxmemory` ограничивает данные Valkey, а не весь RSS:
контейнеру нужен дополнительный запас на служебную память.

## Изображения

Параметры API задаются в `api.env` на сервере или `apps/api/.env` в разработке:

| Параметр                      | По умолчанию | Назначение                                                  |
| ----------------------------- | -----------: | ----------------------------------------------------------- |
| `IMAGE_DOWNLOAD_CONCURRENCY`  |            8 | Общий предел активных загрузок страниц и исходников обложек |
| `IMAGE_TRANSFORM_CONCURRENCY` |            1 | Параллельные преобразования Sharp                           |
| `IMAGE_DOWNLOAD_QUEUE_LIMIT`  |          128 | Очередь перед загрузкой, без скачанных тел                  |
| `IMAGE_TRANSFORM_QUEUE_LIMIT` |           32 | Очередь перед преобразованием                               |
| `IMAGE_QUEUE_TIMEOUT_MS`      |         2000 | Максимальное ожидание в каждой очереди                      |

При заполнении очереди или истечении ожидания API возвращает 429 с `Retry-After: 1`.
Слот загрузки обложки удерживается и во время ожидания Sharp: скачанные тела не могут
накопиться сверх числа допущенных загрузок. Одинаковые преобразования объединяются.
Для страниц слот удерживается до окончания отправки ответа; закрытие клиента отменяет
его ожидание и запрос к источнику. Кешированные обложки не требуют скачивания и Sharp.

Дополнительные пределы:

- исходное или распакованное тело — до 16 МиБ;
- преобразуемый исходник — до 20 миллионов пикселей;
- запрошенная ширина — целое число от 1 до 1440;
- кеш операций Sharp — 16 МиБ;
- запрос к источнику ограничен `SOURCE_HTTP_TIMEOUT_MS` (по умолчанию 20 секунд).

Увеличение параллельности и размеров очередей повышает расход памяти и задержки.
На личном VPS с 1 ГиБ сначала используйте значения по умолчанию. Результаты локальных
нагрузочных проверок и их ограничения описаны в [отчёте](../tests/load/RESULTS.md).

В dev отдельный кеш доступен на `localhost:6380` (`CACHE_PORT` в корневом `.env`),
адрес API задаётся через `CACHE_REDIS_URL`. Счётчики используют прежний `REDIS_URL`.
