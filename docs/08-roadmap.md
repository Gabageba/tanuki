# 08 — Roadmap

Оценки — для одного разработчика на полной занятости. Делите на свою реальную занятость.
Порядок фаз важнее оценок: он выстроен так, чтобы главный риск проекта вскрылся на второй
неделе, а не на третьем месяце.

**Итого до публичной беты: ~15–19 недель.**

> **Обновление (2026-08):** Фазы 1–2 ниже описывают исторический путь через JVM-сайдкар
> (`apps/parsers`, Ktor + `kotatsu-parsers-redo`) — так проект строился и работал до этого
> момента, чеклисты ниже отражают, что тогда было сделано. Впоследствии сайдкар заменён на
> `packages/parsers` — TS-порт логики 23 русских источников, импортируемый в процесс `apps/api`
> без сетевого хопа. Подробности и причины — [03 — Слой парсеров](03-parsers.md),
> лицензионные следствия (весь репозиторий теперь GPLv3) — [09 — Правовые аспекты](09-legal.md).
> Actionable-пункты по антиботу/устойчивости из Фазы 2 остаются в силе, пункты про Gradle/Ktor/
> JitPack — нет, `apps/parsers` в репозитории больше не существует.

- [ ] `packages/tsconfig` — базовые конфиги (`base`, `react-app`, `node-app`)

- [ ] `apps/api` — скелет NestJS 11 на Fastify, `/health`, pino-логи

## Фаза 1 — Вертикальный срез

**~2.5 недели.** Цель: один источник проходит весь путь от каталога до прочитанной
страницы. Это самая важная фаза — она проверяет, что вся архитектура вообще работает.

- [ ] `apps/parsers` — Ktor-скелет, Gradle, зависимость на `kotatsu-parsers-redo`
      **(первым делом: сверить актуальные координаты и тег на JitPack — см. [03](03-parsers.md))**
- [ ] Реализация `MangaLoaderContext` для серверного окружения (без Android WebView)
- [ ] Эндпоинты сайдкара: `/sources`, `/list`, `/details`, `/pages`
- [ ] **Один источник — Desu** (открытый JSON API, минимум сюрпризов)
- [ ] Dockerfile для сайдкара, добавление в compose
- [ ] `apps/api`: `SourcesModule`, `CatalogModule`, нормализация → доменная модель
- [ ] `apps/api`: `/img` — прокси с HMAC-подписью, стриминг через undici, Referer
- [ ] `apps/web`: страница каталога (сетка карточек, бесконечная лента)
- [ ] `apps/web`: страница тайтла (описание, список глав)
- [ ] `apps/web`: **минимальная читалка** — вертикальный скролл, кнопка «следующая глава»

**Готово, когда:** вы открыли приложение, нашли тайтл, открыли главу и прочитали её до
конца. Некрасиво — нормально. Работает — обязательно.

**Главный риск фазы:** `MangaLoaderContext` без WebView. Если исполнение JS окажется
необходимым уже для Desu — это меняет планы (понадобится headless-браузер как ещё один
сайдкар). Лучше узнать это на второй неделе, чем на десятой.

## Фаза 2 — Парсеры в полную силу

**~2 недели.** Цель: все приоритетные русские источники и устойчивость к их поломкам.

- [x] Подключение источников P0: ReadManga, MintManga, SelfManga (Grouple) — включены через
      `ENABLED_SOURCES`; MintManga/SelfManga требуют доп. работы с авторизацией/возрастным
      гейтом Grouple-сети, см. `docs/03-parsers.md#решение-по-антиботу-фаза-2`
- [x] Подключение P1: Remanga, ~~Newmanga~~ — Newmanga пропущен: парсера для него нет в форке
      `tanuki-parsers-redo` вообще, 6 остальных источников и так закрывают критерий "6+"
- [x] **MangaLib** — отдельно и последним, он сложнее всех остальных вместе взятых
- [x] Решение по антибот-защите: headless-браузер сайдкаром / прокси-пул / отказ от
      проблемных источников. Решать по факту, а не заранее — решили не поднимать headless,
      см. `docs/03-parsers.md#решение-по-антиботу-фаза-2`
- [x] Кеш в Valkey: TTL по типам сущностей, ключи с `sourceId`
- [x] Stale-while-revalidate — отдаём протухшее, когда источник лежит
- [x] Circuit breaker + rate limiter на источник
- [x] `status: ok | degraded | down` в `/sources`, отображение в UI
- [x] Мультипоиск по источникам с общим дедлайном
- [x] **Ветки переводов** — группировка, выбор дефолтной, селектор в UI (были готовы ещё до
      начала этой фазы)
- [x] Контрактные тесты источников + ночной CI-джоб

**Готово, когда:** 6+ русских источников работают, отключение любого из них не ломает
приложение, а тайтл с пятью командами перевода отображается вменяемо.

## Фаза 3 — Читалка

**~3 недели.** Цель: то, ради чего продукт существует. Самая объёмная фаза.

- [ ] Вертикальный непрерывный режим с виртуализацией окна ±3 страницы
- [ ] Постраничные режимы: RTL, LTR
- [ ] Резервирование места под неподгруженные страницы (по `width`/`height` из API)
- [ ] Prefetch следующих N страниц + первых страниц следующей главы
- [ ] Бесшовный переход между главами внутри одного скролл-контейнера
- [ ] Жесты: pinch-zoom, double-tap, свайп, зоны тапа
- [ ] Клавиатура: стрелки, пробел, `F`, `M`, Home/End
- [ ] Автоскрытие UI по бездействию, панель настроек
- [ ] Настройки: отступы, ширина контента, яркость, фон, качество, глубина префетча
- [ ] Сохранение прогресса в Dexie (debounce 1 с + flush на выходе)
- [ ] Wake lock, фуллскрин
- [ ] Режим разворота для планшетов _(можно отложить в P2)_

**Готово, когда:** глава на 200 страниц листается на среднем Android в 60 fps, прогресс
не теряется при закрытии вкладки, а переход между главами не требует захода в меню.

## После релиза

Не в скоупе первой версии, но стоит держать в голове при проектировании:

| Идея                                   | Комментарий                                                  |
| -------------------------------------- | ------------------------------------------------------------ |
| Рекомендации по истории чтения         | Считаются на клиенте по тегам — без сбора данных на сервере  |
| Списки и подборки пользователей        | Требует модерации, это отдельный продукт внутри продукта     |
| Трекеры (Shikimori, MAL, AniList)      | Shikimori — самый востребованный у русской аудитории         |
| Telegram-бот уведомлений о главах      | Дёшево, а для RU-аудитории попадает точно в привычки         |
| Импорт библиотеки из Tachiyomi/Kotatsu | Сильный аргумент для перехода, формат бэкапов документирован |
| Нативная обёртка (Capacitor)           | Только если упрётесь в лимиты хранилища на iOS               |

## Порядок принятия рискованных решений

Три вопроса, ответы на которые могут поменять план. Все они специально вынесены как
можно раньше:

1. **`MangaLoaderContext` без WebView** (Фаза 1). Заработает ли библиотека вне Android.
2. **Антибот на MangaLib** (Фаза 2). Может потребовать headless-браузера или отказа от
   источника. Не начинайте с него.
3. **Квоты хранилища на iOS** (Фаза 4). Может ограничить офлайн-сценарий на Apple.

Если что-то из этого пойдёт не по плану, вы узнаете об этом, имея работающий продукт на
других источниках — а не переписывая всё с нуля.
