Слои — упрощённый FSD. Правило одно и оно линтится: `shared` ← `entities` ← `features`
← `pages` ← `app`. Импорты вверх по слоям запрещены `no-restricted-imports`.

### Как определить слой файла

Не «на что это похоже», а что файл импортирует / кто имеет право его импортировать. Идём
по вопросам снизу вверх, останавливаемся на первом «да»:

1. **Не знает о домене вообще?** Обёртка над библиотекой, API-клиент, generic-хук,
   форматтер, чистый UI без бизнес-данных — вынеси в npm-пакет, ничего не сломается →
   `shared`.
2. **Описывает бизнес-сущность саму по себе**, вне сценария? Как выглядит «тайтл»,
   «источник» — карточка, бейджи, форматирование полей, но не то, что с этим делает
   конкретный экран → `entities`.
3. **Законченное действие пользователя**, возможно поверх нескольких entities? «Добавить
   в закладки», «переключить источник», читалка как механика — отвечает на «что можно
   сделать», а не «что нарисовано» → `features`.
4. **Существует ровно для одного маршрута/экрана**, собирает features/entities в
   конкретный вид, больше нигде не переиспользуется → `pages`.
5. **Нужно видеть/собирать несколько `pages` разом**, либо это глобальный каркас —
   роутер, провайдеры, тема, шапка/футер вокруг всех страниц → `app`. Единственный слой
   без ограничений на импорт.

Практический тест: возьми свои импорты, найди **самый нижний** слой, где они все ещё
разрешены правилом п.1 — это и есть твой слой. Не `features` по умолчанию, потому что
лень думать.

**Глубина внутри слоя** — по числу потребителей: код лежит рядом со своим единственным
потребителем; в общее место на уровне слоя поднимается, только когда потребителей больше
одного. Пример: хук, который использует только один компонент, живёт в его `hooks/`, а не
в `shared/hooks/`; как только появляется второй потребитель — поднимаем.

### Общая карточка тайтла

Единственный `TitleCard` находится в `entities/title/card/TitleCard/TitleCard.tsx`.
Это компонент сущности: он сам строит ссылку, рисует обложку и маркеры, скрывает 18+,
показывает причину недоступности, название с точкой обновлений и описание. В shared
остаются низкоуровневые `CoverImage`, `TextSkeleton` и другие общие UI-компоненты.

В корне `TitleCard/` лежат готовая карточка, её скелетон и история, общие модели,
стили, контекст и helpers. Внутренняя разметка находится в `components/`: плитка
`TitleCardGrid/` и список `TitleCardList/` со своими скелетонами, обложка
`TitleCardCover/` с декорациями и причиной недоступности, название `TitleCardName/`
с точкой обновлений и собственным `hooks/useFirstLineEnd`. Описание лежит рядом
со списком — своим единственным потребителем. Общий `hooks/useTitleCardLayout`
остаётся в корне; импорты компонентов ведут прямо к их файлам.

Публичный API — `data`, `viewMode`, `listSize`, `showSource`, React-слоты `meta` / `footer`
и массив `actions`. `TitleCardData` — небольшая модель отображения: общие
поля тайтла, оценка, папка, признак новых глав и доступность. Серверные DTO не меняются.
Обёртки подготавливают данные и содержимое слотов:

- `SourceTitleCard` — `Title` из каталога, поиска, подборок и совпадений;
- `BookmarkCard` — метаданные источника назначения из общего снимка (иначе личного резерва), прогресс и меню;
- `ContinueReadingCard` — позиция и время чтения, меню удаления;
- `NewChapterRow` — источник, тип и данные новых глав.

`SourceTitleCard` находится в `entities/source/components/SourceTitleCard/`: готовая
композиция, её скелетон и история лежат в корне, метаданные, нижняя строка
и теги — в `components/`. Хук измерения тегов находится внутри `TitleCardTags/hooks/`.
Этот модуль использует общий `entities/title/card/TitleCard/`; тот используется также
композициями закладок и главной. Сетки и лента карточек остаются в `entities/title/card/`.

Плитка и список имеют отдельную читаемую разметку `TitleCardGrid` / `TitleCardList`.
Корневой компонент выбирает её через `switch (viewMode)`. Внутренний контекст содержит
только `viewMode` / `listSize`; обложка, название и метаданные читают его через
`useTitleCardLayout`. Обёртки не сравнивают виды и не передают объекты `grid` / `list`.
Название, описание, маркеры и оверлеи больше не являются внешними слотами.

`TitleCardDecorations` — внутренняя часть обложки для всех карточек: рейтинг,
лента источника и метка папки. Общий `TitleCardMetaRow` выводит `TitleAdultTag` высотой
20 px справа в мета-строке во всех видах, включая плитку. Без метаданных тег и меню
переходят к первой строке названия. В виде без обложки там же находится метка папки;
у карточек с обложкой папка остаётся на изображении. Недоступность
обесцвечивает и слегка размывает обложку, приглушает название и скрывает точку;
при скрытом 18+ сохраняется сильное размытие, а глаз заменяется причиной недоступности.
Точка измеряет конец первой строки и учитывает загрузку шрифта.

В `BookmarkCard` с 2026-11-06 используется [N18](11-ui-decisions.md#новые-главы-в-карточке-закладки-n18):
прогресс окрашивается в оранжевый при новых главах, точка и её отступ у названия не передаются.
Без обновлений и при недоступности источника прогресс остаётся серым.

`actions` — массив `TitleCardAction` на основе Mantine `MenuItemProps`: `children`,
`leftSection`, `rightSection`, `disabled`, `color`, `closeMenuOnClick` и остальные свойства
передаются прямо в `Menu.Item`. Дополнительно задаются `id`, необязательная `group` и
обработчик `onClick` либо ссылка `to`. `TitleCard` сам создаёт кнопку и меню
через внутренний `TitleCardActions`, вне растянутой ссылки. Общая группа получает заголовок,
между группами добавляется разделитель; пустой массив скрывает кнопку.
Композиции сохраняют своё состояние и модалки рядом с карточкой.
Размер кнопки 24 px задан в `TITLE_CARD_ACTION_SIZE`; её ширина и высота учитываются
в строке метаданных. Пустые слоты скрываются CSS, включая компонент,
вернувший `null`; числовой ноль в метаданных скрывается. Описание и `footer` монтируются
только в списке.

`TitleCardSkeleton` имеет собственные лёгкие `TitleCardGridSkeleton` /
`TitleCardListSkeleton`, обычный `Skeleton` для обложки и автоматический `TextSkeleton`
для названия. Его API — тот же выбор раскладки, слоты `meta` / `footer`,
`withActions` для общего скелетона кнопки и `withDescription` для подробного списка.
Плейсхолдер действия создаётся внутри `TitleCardSkeleton`: композиции не передают свой
`actions`. Кнопка и её скелетон используют один `TITLE_CARD_ACTION_SIZE` без внешних
переопределений размеров. Видимая плашка ограничена высотой текста, место под кнопку
резервируется целиком. Готовая карточка, её изображение и оверлеи
в скелетон не импортируются; нет фиктивных DTO, ссылок и флага загрузки у готовой карточки.
Корень `inert` / `aria-hidden`, время показа задают прежние механизмы загрузки.

Реализовано 2026-11-03 по [плану](plans/unified-title-card.md). Истории общего компонента
и композиций находятся в группе «Карточки». Прежний `shared/ui/TitleCard`,
`CatalogTitleCard`, отдельные `BookmarkTitle` / `BookmarkCover` и старые раскладки удалены.
Отдельная обложка сохранённых макетов главной — локальный
`Playground/Home/components/MockTitleCardImage`; вид макетов сохранён.

## Состояние

Пользовательская часть приложения требует вход, поэтому данные — закладки, прогресс, настройки
читалки и приложения — живут на сервере, а не в браузере. Хранилищ на клиенте два:

| Что                                                                      | Где                | Почему                                                        |
| ------------------------------------------------------------------------ | ------------------ | ------------------------------------------------------------- |
| Данные с сервера (каталог, тайтлы, главы, закладки, прогресс, настройки) | **TanStack Query** | Кеш, ретраи, инвалидация, дедупликация запросов — всё готовое |
| Фильтры каталога, вкладки, страница в читалке                            | **URL**            | Шарится ссылкой, работает кнопка «назад»                      |

Состояние читалки (позиция, видимость панелей) — локальный state её компонентов, отдельного
стора нет. Dexie (IndexedDB) появится только вместе с офлайном — для очереди скачанных глав и
их метаданных (см. [06](06-pwa-offline.md)); local-first синхронизации не будет.

Уведомления: `useNotificationsStream` держит одно соединение SSE на вкладку (монтируется в
`app/RequireAuth` через `NotificationsStream`, чтобы работать и в читалке вне `Layout`; поток,
закрытый ответом не 200, переподключается с растущей паузой) и на каждое событие инвалидирует ленту и счётчик; пока поток не подключён,
`useUnreadNotificationsCount` опрашивает `/notifications/unread-count` раз в минуту. Лента —
`useInfiniteQuery` (страницы с единицы, `PageLayout.InfiniteScrollTrigger`).

### Общие тосты

С 2026-11-10 все рабочие тосты используют `shared/lib/toasts/` и
`shared/ui/Toast/ToastHost.tsx`. Хост подключён в `main.tsx`; `app/Toasts/AppToastHost.tsx`
измеряет существующую нижнюю панель, `RouteLayout` передаёт режим читалки.
Очередь и таймеры живут в одном механизме: видна нижняя тройка сообщений, верх временно скрыт
с сохранением таймеров и действий; после закрытия новых прежние возвращаются. Есть
временное скрытие PWA без отказа и паузы на наведении, фокусе и скрытой
вкладке. Общий тон — `FEEDBACK_TONE` из `shared/lib/feedback.ts`.

Фоновые SSE-события ждут выхода из читалки, безопасность и результаты текущих действий
видны сразу. Повторы объединяются по смысловым ключам, смена аккаунта очищает его очередь
и обработчики. Предметные действия передаются ReactNode-слотами и остаются рядом со
своими потребителями. Внутри модалки/drawer портал входит в FocusTrap, а нативный
`popover="manual"` сохраняет размещение относительно экрана поверх CSS-transform.
Подробнее — [план общих тостов](plans/global-toasts.md).

### Загрузка

Когда показать скелетон, решает не блок, а общий механизм (`shared/ui/QueryBlock`, правило
**Loading** в `CLAUDE.md`, решение — «Концепция 2026-10-21» в [11](11-ui-decisions.md)):

- **`PageLayout.Content skeleton={…}`** — для главного запроса страницы (или всех именованных из
  `useQueries`, их сводит `mergePageQueries`). Без `skeleton` содержимое рисуется сразу, а
  загрузку показывают блоки сами.
- **`<QueryBlock query skeleton empty isEmpty>{(data) => …}</QueryBlock>`** — для блока со своим
  запросом; `empty` — что показать, если запрос упал без данных или ответ пуст по `isEmpty`
  (`isEmpty={({ total }) => total === 0}`), — проверку пустоты не повторяют внутри `children`.
  Содержимое берёт данные из аргумента `children`, а не из `query.data` снаружи; когда разметки
  много, её выносят в компонент, которому эти данные передают (`<SettingsSourcesList data />`).
  Блок, который ждёт несколько запросов, передаёт их массивом
  (`query={[sourceQuery, filtersQuery]}`, сводит `mergeQueries`), а данные получает кортежем в
  том же порядке. Компонент с собственным `loading` (как `GroupedList`) берёт тайминг у хука
  `useSkeletonTiming(query).isSkeleton`.
- Решение по состоянию запроса (`getQueryLoad`): данных нет — скелетон сразу; устаревшие данные
  при монтировании — скелетон сразу; данные на экране, но идёт запрос за новыми
  (`keepPreviousData`, фокус вкладки, инвалидация) — через `SKELETON_DELAY_MS` (200 мс), держится
  не меньше `SKELETON_MIN_MS` (400 мс), верх блока поднимается из-под шапки. Тихо идут подгрузка
  следующей порции и перезапрос живых данных (`isLive: true` в результате хука — опрос здоровья
  источников, лента уведомлений по SSE). Без сети и без данных — `OfflineState`; данные есть —
  показываются как есть.
- Свежесть — `staleTime`: по умолчанию 5 минут (`QueryClientProvider`), перезапрос при фокусе
  вкладки включён. Мутация, обновившая кеш оптимистично (`setQueryData`), не инвалидирует его на
  успехе — только откатывает на ошибке.
- Поиск — исключение «из частей»: `useSearch` на `streamedQuery` читает поток SSE
  (`apiStream`), места источников рисуются по `sourceIds`, неответившие — скелетоном секции.

Прогресс чтения пишется в кеш TanStack Query сразу, а на сервер — с задержкой 2 секунды и
немедленно при уходе из читалки, скрытии или закрытии вкладки (`useSaveReadingProgress`).

## Читалка

Это ядро продукта. Всё остальное — обвязка вокруг неё. Пишется полностью вручную,
Mantine здесь используется только для оверлея настроек.

Режимы и механика ниже реализованы; проверка плавности на среднем Android остаётся
пунктом приёмки в [плане](plans/reader-improvements.md).

### Режимы

| Режим                                  | Для чего                           | Приоритет                                    |
| -------------------------------------- | ---------------------------------- | -------------------------------------------- |
| **Вертикальный непрерывный (webtoon)** | Манхва, корейские/китайские тайтлы | **P0** — для RU-аудитории это основной режим |
| Постранично RTL                        | Классическая японская манга        | P0                                           |
| Постранично LTR                        | Комиксы, часть переводов           | P1                                           |
| Разворот (2 страницы)                  | Телефоны, планшеты, компьютеры     | P2                                           |

Вертикальный режим идёт первым не по алфавиту: значительная доля того, что читают на
русских источниках — манхва, а её читают только скроллом.

### Технические требования

- **Виртуализация.** Лёгкие обёртки всех страниц сохраняют геометрию ленты; изображения
  монтируются в окне ±3 страницы вокруг всех реально видимых. Размеры берутся из `width`/`height`,
  затем уточняются по изображению и сохраняются при демонтаже. Постранично монтируется текущая
  страница или пара. Восстановленная позиция удерживается до собственного движения читателя.
- **Prefetch.** Следующие 0–10 страниц (по умолчанию 3) грузятся и декодируются очередью
  `new Image()`, не более двух одновременно. Граница следующей главы входит в общий лимит только
  при автопереходе. Нулевая глубина не запрашивает соседние изображения; при выключенном
  автопереходе не запрашиваются и метаданные следующей главы. Офлайн предзагрузка выключена.
- **Резервирование места.** Плейсхолдер той же высоты, что и картинка, иначе скролл
  прыгает при подгрузке. Самый заметный дефект чтения на мобильном.
- **Жесты.** Pinch-zoom, double-tap для зума, свайп между страницами, тап по зонам
  (левая треть / правая треть / центр = меню). Реализуется через Pointer Events, не через
  библиотеку — готовые решения плохо дружат с виртуализацией.
- **Клавиатура.** `←`/`→`, `Space`/`Shift+Space`, `Home`/`End`, `F` — фуллскрин, `M` —
  сменить режим. `useReaderKeyboard` обрабатывает клавиши до снятия удержания прокрутки;
  поля ввода, кнопки, меню, диалоги, модифицированные сочетания и повторы клавиши не перехватываются.
- **Сохранение прогресса.** На сервер с задержкой 2 секунды, при выходе из читалки —
  немедленно.
- **Скрытие UI.** Шапка и панель глав уезжают при прокрутке вниз (настройка
  `hidePanelsOnScroll`) и прячутся/возвращаются тапом в центр. Автоскрытия по бездействию
  нет — решили не делать.
- **Wake lock и fullscreen.** Блокировка экрана выключена по умолчанию, освобождается при
  скрытии вкладки и выходе, повторно запрашивается при возврате. Полный экран включается только
  кнопкой или `F`; внешнее завершение синхронизирует кнопку, уход из читалки завершает режим.
  Отсутствие поддержки скрывает кнопку, отказы обоих API не прерывают чтение.
- **Плавный переход между главами.** Долистал до конца → следующая глава подгружается
  в тот же скролл-контейнер без выхода в меню.

### Настройки читалки

Хранятся на сервере (`/reader-settings`), применяются мгновенно. Есть: режим (вертикальный /
постраничный), вписывание страницы, ширина контента, ширина зон тапа, отступы между
страницами и между главами, автопереход к следующей главе, скрытие панелей при прокрутке.
Также доступны направление LTR/RTL, одна страница или разворот, яркость 20–100% (затемняются
только изображения), предзагрузка 0–10 страниц и запрет гашения. Фон читалки, включая загрузку,
следует за темой приложения; отдельного выбора фона нет.
Развороты начинаются с пары 1–2, выровнены сверху и вписаны в экран, последняя непарная страница
по центру. Прогресс хранит первую страницу пары, прочтение учитывает последнюю в паре. Скрытые
настройки сохраняются: направление, разворот и зоны — только постранично; отступы — вертикально;
ширина контейнера — при масштабе по ширине. Инвертирования и выбора качества изображений не будет.

Те же настройки, что в drawer читалки, есть на вкладке «Читалка» в настройках — см.
[Настройки читалки](11-ui-decisions.md#настройки-читалки). Выбранные изменения обоих мест и панели
чтения описаны в [«Возможностях читалки»](11-ui-decisions.md#возможности-читалки).

## Решения по макетам

Песочница `/playground/*` работает только в dev-режиме и открывается без входа, API и Docker:
`pnpm dev:playground` собирает contracts и запускает только web. В `RouterProvider` её ленивый
маршрут находится вне `RequireAuth`, а `app/PlaygroundRouter` подключает отдельный
`PlaygroundLayout` с переходом к списку макетов и переключателем темы. Переиспользованные
компоненты получают отдельный кеш с выключенными запросами, гостевым состоянием и локальными
настройками; кеш настоящей сессии не меняется. `UserSettingsSync` монтируется внутри
`RequireAuth` после проверки входа. В production ветка `import.meta.env.DEV` исключает
маршрут и импорт песочницы вместе с её каркасом и провайдерами.

## Storybook

`pnpm storybook` (порт 6006) показывает настоящие компоненты в состояниях, до которых в
приложении добираться долго: все страницы (обычная, на телефоне, загрузка со скелетонами, ошибка,
пустое состояние, вкладки), модалки и их шаги, drawer’ы, меню, тосты, экраны ошибок, карточки и
компоненты `shared/ui`. Песочница — для
выбора между вариантами, Storybook — для проверки того, что уже в коде.

- Провайдеры — те же, что у приложения (`.storybook/StoryProviders.tsx`): тема, i18n, свой
  QueryClient на историю, роутер в памяти. Язык и тема переключаются в тулбаре.
- Страница монтируется на своём маршруте внутри каркаса приложения (`app/Layout` или
  `app/AuthLayout`) — `parameters.route` (`.storybook/StoryRoutes.tsx`).
- Сеть — MSW (`shared/storybook/handlers.ts`): чтения отвечают данными из `shared/storybook/`
  (`fixtures.ts`, `titles.ts`, `account.ts`; обложки и страницы глав рисует `images.ts`),
  изменения — успехом, на бэкенд не уходит ничего. `LOADING_HANDLERS` и `ERROR_HANDLERS`
  держат всю страницу в загрузке или роняют её запросы. История
  перекрывает ответ через `parameters.msw`.
- Истории лежат рядом с компонентом (`DeleteUserModal.stories.tsx`) и в сборку приложения не
  попадают — как и `shared/storybook/`.

## Производительность

Целевые метрики на среднем Android (Snapdragon 6-го класса, 4G):

| Метрика                        | Цель              |
| ------------------------------ | ----------------- |
| LCP на каталоге                | < 2.5 с           |
| Время до первой страницы главы | < 1.5 с           |
| Скролл в webtoon-режиме        | стабильные 60 fps |
| Размер основного бандла        | < 200 КБ gzip     |

Что для этого делаем: код-сплит по маршрутам, `@mantine/core` через модульные импорты,
`content-visibility: auto` на карточках каталога, `loading="lazy"` + `decoding="async"`
на обложках, AVIF/WebP с фолбэком, `IntersectionObserver` для бесконечной ленты.

## Интернационализация

Русский — основной и дефолтный язык. Английский — вторым, ради контрибьюторов.
`i18next` + `react-i18next` (те же пакеты, что в `gabageba-ui`). Даты — через `Intl`,
а не Luxon: одна библиотека экономится, а форматирование дат тут тривиальное.

Отдельно: названия тайтлов и жанров **не переводим** — они приходят от источника уже на
русском.

## Доступность

Читалка — это в первую очередь текст и картинки, но базовое соблюдать обязательно:
навигация с клавиатуры по всем маршрутам, видимый фокус, `alt` на страницах
(«Страница N из M»), `prefers-reduced-motion` отключает анимации переходов,
контраст AA в обеих темах. `eslint-plugin-jsx-a11y` уже в конфиге.

### Карточки блоков без обложек

`TitleCard` и `TitleCardSkeleton` выбирают раскладку через `viewMode`, включая `VIEW_MODE.COVERLESS`.
Итоговый режим блока определяется как `section.viewMode ?? viewMode`, где второй — сохранённый вид пользователя.
`coverless` использует `TitleCardCoverless`: общая мета-строка типа/года/глав (или страниц)
сверху, затем до двух строк названия и описания. Маркеры папки и 18+ находятся справа
в мета-строке, а при её отсутствии — в строке названия. Теги и лайки выровнены по нижнему
краю, карточки одного ряда растягиваются до одинаковой высоты. `TitleCardsGrid` и скелетон располагают карточки в две колонки на десктопе и одну на телефоне.
Отсутствие обложки у отдельного тайтла не меняет его вид. Переключатель обычных блоков
по-прежнему предлагает сетку и список; режим без обложек задаётся метаданными блока.

В `pages/Selections` месяц и порядок находятся в URL (`variant`, `order`) и query key.
Панель `CoverlessSectionPanel` показывает календарный месяц и сортировку; у обычных блоков
остаётся прежняя панель с переключателем вида. Неверные периоды и порядки заменяются
первым поддерживаемым с `replace`, в том числе при обновлении метаданных источника.
Загрузка идёт через `QueryBlock`, пустая выдача и ошибки сохраняют общие состояния.
Решение — [C2 + T1a + M9 + P2 + L2](11-ui-decisions.md#карточка-тайтла-без-обложки).

Общий снимок библиотеки (2026-11-11) не меняет компоненты, контракты, состояния Storybook
или загрузку: следующая обычная выдача API приносит свежие метаданные карточек. Отдельной
подписки SSE на смену обложки нет. См. [план](plans/shared-title-snapshot.md).
