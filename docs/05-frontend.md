# 05 — Фронтенд

## Структура

```
apps/web/src/
├── app/
│   ├── router.tsx              # react-router, ленивые чанки по маршрутам
│   ├── providers.tsx           # Mantine, QueryClient, i18n, ErrorBoundary
│   └── theme.ts                # тема Mantine, тёмная по умолчанию
├── pages/
│   ├── Home/                   # продолжить чтение + обновления библиотеки
│   ├── Catalog/                # список тайтлов источника, фильтры
│   ├── Search/                 # мультипоиск
│   ├── Title/                  # карточка тайтла, ветки, список глав
│   ├── Reader/                 # читалка
│   ├── Library/                # сохранённое, история, загрузки
│   └── Settings/
├── features/
│   ├── reader/                 # ядро читалки — самая объёмная часть
│   ├── library/
│   ├── downloads/
│   └── sources/
├── entities/
│   └── title/                  # карточки, бейджи, форматтеры
├── shared/
│   ├── api/                    # клиент + хуки TanStack Query
│   ├── db/                     # схема Dexie
│   ├── ui/                     # обёртки над Mantine
│   ├── hooks/
│   └── lib/
└── styles/
    ├── _tokens.scss
    └── global.scss
```

Слои — упрощённый FSD. Правило одно и оно линтится: `shared` ← `entities` ← `features`
← `pages` ← `app`. Импорты вверх по слоям запрещены `no-restricted-imports`.

### Как определить слой файла

Не «на что это похоже», а что файл импортирует / кто имеет право его импортировать. Идём
по вопросам снизу вверх, останавливаемся на первом «да»:

1. **Не знает о домене вообще?** Обёртка над библиотекой, API-клиент, generic-хук,
   форматтер, чистый UI без бизнес-данных — вынеси в npm-пакет, ничего не сломается →
   `shared`.
2. **Описывает бизнес-сущность саму по себе**, вне сценария? Как выглядит «тайтл»,
   «источник» — карточка, бейджи, форматирование полей, но не то, что с этим делает
   конкретный экран → `entities`.
3. **Законченное действие пользователя**, возможно поверх нескольких entities? «Добавить
   в закладки», «переключить источник», читалка как механика — отвечает на «что можно
   сделать», а не «что нарисовано» → `features`.
4. **Существует ровно для одного маршрута/экрана**, собирает features/entities в
   конкретный вид, больше нигде не переиспользуется → `pages`.
5. **Нужно видеть/собирать несколько `pages` разом**, либо это глобальный каркас —
   роутер, провайдеры, тема, шапка/футер вокруг всех страниц → `app`. Единственный слой
   без ограничений на импорт.

Практический тест: возьми свои импорты, найди **самый нижний** слой, где они все ещё
разрешены правилом п.1 — это и есть твой слой. Не `features` по умолчанию, потому что
лень думать.

**Глубина внутри слоя** — по числу потребителей: код лежит рядом со своим единственным
потребителем; в общее место на уровне слоя поднимается, только когда потребителей больше
одного. Пример: хук, который использует только один компонент, живёт в его `hooks/`, а не
в `shared/hooks/`; как только появляется второй потребитель — поднимаем.

## Состояние

Три хранилища с непересекающимися зонами ответственности:

| Что                                                  | Где                   | Почему                                                        |
| ---------------------------------------------------- | --------------------- | ------------------------------------------------------------- |
| Данные с сервера (каталог, тайтлы, главы)            | **TanStack Query**    | Кеш, ретраи, инвалидация, дедупликация запросов — всё готовое |
| Состояние читалки (режим, зум, текущая страница, UI) | **Zustand**           | Меняется часто, ререндеры должны быть точечными               |
| Библиотека, история, прогресс, офлайн-главы          | **Dexie (IndexedDB)** | Переживает перезагрузку, работает офлайн, это источник истины |
| Фильтры каталога                                     | **nuqs (URL)**        | Шарится ссылкой, работает кнопка «назад»                      |

Прогресс чтения пишется **в Dexie немедленно**, и отдельным фоновым процессом
синхронизируется с сервером. Не наоборот. Сеть в метро отваливается, прогресс теряться
не должен.

### Схема Dexie

```ts
db.version(1).stores({
  library: '&id, sourceId, addedAt, lastReadAt',
  progress: '&[titleId+branch], titleId, updatedAt, syncedAt',
  history: '++id, titleId, readAt',
  downloads: '&[titleId+chapterId], titleId, status, downloadedAt',
  titleCache: '&id, cachedAt', // метаданные для офлайн-просмотра
});
```

`syncedAt` в `progress` — маркер для фоновой синхронизации: всё, где `updatedAt >
syncedAt`, уходит на сервер батчем.

## Читалка

Это ядро продукта. Всё остальное — обвязка вокруг неё. Пишется полностью вручную,
Mantine здесь используется только для оверлея настроек.

### Режимы

| Режим                                  | Для чего                           | Приоритет                                    |
| -------------------------------------- | ---------------------------------- | -------------------------------------------- |
| **Вертикальный непрерывный (webtoon)** | Манхва, корейские/китайские тайтлы | **P0** — для RU-аудитории это основной режим |
| Постранично RTL                        | Классическая японская манга        | P0                                           |
| Постранично LTR                        | Комиксы, часть переводов           | P1                                           |
| Разворот (2 страницы)                  | Планшеты, ландшафт                 | P2                                           |

Вертикальный режим идёт первым не по алфавиту: значительная доля того, что читают на
русских источниках — манхва, а её читают только скроллом.

### Технические требования

- **Виртуализация.** Глава может быть 200+ страниц по 2 МБ. В DOM держим окно ±3
  страницы, остальное — плейсхолдеры фиксированной высоты (отсюда важность `width`/
  `height` из API).
- **Prefetch.** Следующие 3 страницы грузятся заранее через `<link rel="prefetch">` или
  `new Image()`. При переходе на следующую главу — префетч первых 2 страниц следующей.
- **Резервирование места.** Плейсхолдер той же высоты, что и картинка, иначе скролл
  прыгает при подгрузке. Самый заметный дефект чтения на мобильном.
- **Жесты.** Pinch-zoom, double-tap для зума, свайп между страницами, тап по зонам
  (левая треть / правая треть / центр = меню). Реализуется через Pointer Events, не через
  библиотеку — готовые решения плохо дружат с виртуализацией.
- **Клавиатура.** `←`/`→`, `Space`/`Shift+Space`, `Home`/`End`, `F` — фуллскрин, `M` —
  сменить режим. Через `useHotkeys` из Mantine.
- **Сохранение прогресса.** Debounce 1 секунда, запись в Dexie. При выходе из читалки —
  немедленный flush.
- **Автоскрытие UI.** Панели прячутся через 3 секунды бездействия (`useIdle` из Mantine),
  возвращаются по тапу в центр.
- **Wake lock.** `navigator.wakeLock` — экран не должен гаснуть посреди главы.
- **Плавный переход между главами.** Долистал до конца → следующая глава подгружается
  в тот же скролл-контейнер без выхода в меню.

### Настройки читалки

Хранятся в Dexie, применяются мгновенно: режим, направление, отступы между страницами,
ширина контента (для webtoon на десктопе), яркость (CSS-фильтр поверх), цвет фона
(чёрный / серый / бумага), инвертирование, качество изображений (для экономии трафика),
предзагрузка (0–10 страниц).

## Отметки прогресса в списке глав

Решено 2026-09-24 по макетам песочницы (`/playground/reading-marks`, только DEV; страница оставлена как артефакт решения): **A2e + S5 +
стиль «Приглушённо»**. Данные — `GET /titles/:titleId/progress` (см. `04-api-contract.md`).

- **Строка главы (A2e)** — `shared/ui/ChaptersList/ChapterItem.tsx`. Узел на линии — всегда круг
  своего прогресса; своя отметка обведена кольцом акцентного цвета. Чужие отметки — в слоте между
  линией и номером главы: от узла через отступ строки тянется короткая ветка, на её конце иконка
  самого свежего источника и счётчик «+N» в углу (`LinkedMarksIcon`). Ширина слота — одна иконка
  при любом числе источников; слот есть во всех строках, только если отметки есть хоть где-то в
  списке, чтобы номера стояли одной колонкой. Тап по иконке — поповер с отметками и «Продолжить
  отсюда».
- **Сводка под «Продолжить» (S5)** — `pages/Title/components/TitleImageSection/TitleReadingActions.tsx`.
  Если читали на других источниках группы, кнопка становится split-кнопкой «Продолжить | ▾»: в
  меню каждый источник — его глава в ветке «Продолжить» и когда там читали; пункт открывает эту
  главу в читалке, та сама переносит туда свою отметку. Место, которого в ветке нет, выбрать
  нельзя — пункт неактивен, иконка серая, глава показана в нумерации источника.
- **Примерное место** (`confidence: approximate`) — иконка источника приглушена (opacity 0.55) и
  обведена пунктиром, ветка к ней пунктирная, если примерные все отметки на главе. «?»-бейджа и
  «≈» в тексте нет; словами «Место определено примерно» сказано только в поповере.

## Подписи оси у столбчатых графиков

Решено 2026-09-28 по макетам песочницы (`/playground/chart-labels`, только DEV; страница оставлена
как артефакт решения): **L6 — опорные столбики + дата при наведении**. Реализация —
`shared/ui/BarChart.tsx`, первый потребитель — «Прочитано глав» в профиле в режиме «Месяц».

- Пока столбиков не больше 12 (неделя, год), подписан каждый.
- Когда их больше, подписан каждый `labelStep`-й, считая от последнего. У «Прочитано глав» шаг —
  неделя, поэтому все подписи попадают на тот же день недели, что и сегодня. Подпись — «дд.мм»
  моноширинным, у крайних столбиков прижата к краю графика. Подписанные (опорные) столбики чуть
  темнее остальных — так видно, к какому из них относится подпись, которая шире столбика.
- Наведённый столбик подсвечивается, его дата выделенным цветом встаёт на ось прямо под ним, а
  опорные подписи ближе трёх столбиков на это время прячутся. Дата уже на оси, поэтому в подсказке
  остаётся только значение. Наведение ловит вся колонка, так что пустой день тоже можно навести.
- Отвергнуты: риски от столбика к подписи (L0), число + месяц отдельной строкой (L1), только края
  периода (L2), разбивка по неделям с диапазонами (L3), наклонные подписи (L5).

## Производительность

Целевые метрики на среднем Android (Snapdragon 6-го класса, 4G):

| Метрика                        | Цель              |
| ------------------------------ | ----------------- |
| LCP на каталоге                | < 2.5 с           |
| Время до первой страницы главы | < 1.5 с           |
| Скролл в webtoon-режиме        | стабильные 60 fps |
| Размер основного бандла        | < 200 КБ gzip     |

Что для этого делаем: код-сплит по маршрутам, `@mantine/core` через модульные импорты,
`content-visibility: auto` на карточках каталога, `loading="lazy"` + `decoding="async"`
на обложках, AVIF/WebP с фолбэком, `IntersectionObserver` для бесконечной ленты.

## Интернационализация

Русский — основной и дефолтный язык. Английский — вторым, ради контрибьюторов.
`i18next` + `react-i18next` (те же пакеты, что в `gabageba-ui`). Даты — через `Intl`,
а не Luxon: одна библиотека экономится, а форматирование дат тут тривиальное.

Отдельно: названия тайтлов и жанров **не переводим** — они приходят от источника уже на
русском.

## Доступность

Читалка — это в первую очередь текст и картинки, но базовое соблюдать обязательно:
навигация с клавиатуры по всем маршрутам, видимый фокус, `alt` на страницах
(«Страница N из M»), `prefers-reduced-motion` отключает анимации переходов,
контраст AA в обеих темах. `eslint-plugin-jsx-a11y` уже в конфиге.

## Настройка источников

Решено 2026-09-30 по макетам песочницы (`/playground/sources-setup`, только DEV; страница оставлена
как артефакт решения): **S1 + P1 + T1–T3 + I1**. Вход привязан к семейству, а порядок и включение —
к отдельному источнику, поэтому одно и то же не показывается одним списком: экраны разнесены.

- **Настройки → Источники** — один плоский список: порядок и включение. Войти здесь нельзя.
  **S1**: пометка о входе — бейдж сразу за названием, он же ссылка на вкладку аккаунтов
  (`SOURCE_ACCOUNTS_PATH`): цветной «Нужен вход» и «Нужен повторный вход», контурный серый «Вход по
  желанию». У вошедших и у источников без входа пометки нет.
- **Профиль → Аккаунты источников** — семейства с шапкой аккаунта (H3b), без выключателей. **P1**: у
  каждого источника справа бейдж «Вход обязателен» / «Вход по желанию», под названием — «Вход
  даст: …» (тайтлы 18+, тайтлы, скрытые от гостей, импорт закладок). Источник без семейства, в
  который можно войти, — семейство из одного сайта.
- **Экран «закрыто»** — прежний `StatusScreen` под три причины: источник закрыт (**T1**), сессия
  истекла (**T2**), тайтл только для вошедших при открытом источнике (**T3**). Текст называет
  источник и сеть, кнопка — куда войти.
- **Профиль → Данные** — **I1**: строка «Импорт из источника» рядом с импортом из файла. Кнопка
  открывает модалку из трёх шагов: выбор источника (доступны только источники с выполненным
  входом; вид шага — см. «Выбор источника для импорта»), чтение закладок, выбор тайтлов — контент меняется внутри одной модалки, с шага тайтлов
  назад ведёт стрелка в заголовке. Тайтл, чья подтверждённая копия уже в закладках, добавляется к
  ней ещё одним источником, а не дублем.
- Обязательность входа и его польза — свойства источника, а не семейства: внутри одной сети они
  могут различаться.
- Отвергнуты: пометка текстом после домена (S2) и иконкой перед выключателем (S3); обязательность в
  шапке семейства с чипами пользы (P2), иконки с подсказками (P3).
- Сделано: перенос аккаунтов в профиль, пометки S1 в настройках, бейджи и «Вход даст: …» P1. Поля —
  `loginRequirement`, `loginBenefits`, `isLoggedIn` в `Source`. Польза перечисляет только то, что
  вход даёт уже сейчас, но целиком: каталог и чтение глав (каждый источник с обязательным входом),
  главы только для зарегистрированных (MangaLib), купленные главы (LibSocial). Импорта закладок в
  списке нет, пока он заглушка.
- Сделано: порядок источников. Перетаскивание в настройках — `@dnd-kit` (ручка слева, работает и с
  клавиатуры), порядок хранится на сервере (`user_settings.source_order`) и приходит как
  `Source.position`. Сервер отдаёт в этом порядке список источников и группы поиска; совпадения на
  странице тайтла сортирует фронт — внутри каждой группы уверенности.
- Сделано: экраны T1–T3 в `QueryError` — «Источник закрыт» (`sourceAccountRequired`), «Сессия
  истекла» (`sourceReloginRequired`), «Только для вошедших» (`sourceAuthRequired`). Описание — текст
  ошибки с сервера, он называет источник; кнопка — «Войти» или «Войти заново» без названия сети.
- Импорт с источника — пока заглушка (`ImportFromSourceRow` в `pages/Profile/components/ProfileData`):
  сети и состояние входа настоящие, а чтение закладок и список тайтлов — макет, «Импорт» ничего не
  сохраняет и отвечает «Скоро будет доступно».

## Выбор источника для импорта

Решено 2026-09-30 по макетам песочницы (`/playground/import-source-picker`, только DEV; страница
оставлена как артефакт решения): **C1c**. На первом шаге импорта выбирают конкретный источник, а не
сеть.

- Каждая сеть — рамка `GroupedList` с шапкой аккаунта, той же, что на вкладке «Аккаунты
  источников»: иконка и цвет состояния, «Вход выполнен» / «Аккаунт не привязан» / «Нужен повторный
  вход», под ним логин. Так видно и к какой сети относится источник, и чем «входа нет» отличается
  от «войти заново».
- Под шапкой — источники сети строками: логотип, название, радио; строка кликабельна целиком,
  выбранная подкрашена. Источник без входа (`Source.isLoggedIn`) остаётся в рамке приглушённым, без
  радио.
- Войти из модалки нельзя: кнопка в шапке — «Войти» или «Войти заново» — ведёт на вкладку аккаунтов
  (`SOURCE_ACCOUNTS_PATH`). Она есть и у действующего аккаунта LibSocial, если токен получен не для
  всех сайтов сети.
- По умолчанию выбран первый источник с выполненным входом.
- Отвергнуты: радио-список без иконок (C0), отдельные карточки (C1, C1a, C1b), плитка логотипов
  (C2, C2a, C2b), строки-меню под шапкой со свёрнутыми сетями (C3, C1d), выпадающий список (C4),
  меню без кнопки подтверждения (C5).

## Выбор темы

Решено 2026-09-30 по макетам песочницы (`/playground/theme-picker`, только DEV; страница оставлена
как артефакт решения): **T3 — строки списка**. Реализация — `ColorSchemePicker` в
`pages/Settings/components`, первый блок вкладки «Общие».

- Карточки из макета на всю ширину страницы растягивали превью в полосу на десктопе и занимали
  полтора экрана на телефоне. Теперь каждая схема — строка `GroupedList`: миниатюра 52×36 на месте
  иконки, название и пояснение, радио справа. Раскладка одна и та же на любой ширине.
- Строка кликабельна целиком (`Radio.Card`), выбранная подкрашена — как в выборе источника для
  импорта.
- Миниатюра (`ColorSchemePreview`) рисует свою схему статичными шагами `gray`/`dark`, а не ролевыми
  переменными, поэтому не зависит от текущей; «системная» — светлая и тёмная половины по диагонали.
- Отвергнуты: карточки на всю ширину (T0), компактные плитки без пояснений (T1), строка с тремя
  миниатюрами (T2), сегменты с одним превью (T4).
