# 06 — PWA и офлайн

Офлайн — не бонусная фича, а причина делать PWA вместо обычного сайта. Читают в метро,
в самолёте, в поезде. Читалка, которая офлайн показывает белый экран, проигрывает
нативным приложениям по единственному параметру, который в этом сценарии важен.

## Что уже есть: push-уведомления

Из этого документа реализован минимум для Web Push (план — [notifications.md](plans/notifications.md)):
`vite-plugin-pwa` в режиме `injectManifest` **без precache**, `src/sw/sw.ts` с обработчиками
`push` и `notificationclick`, веб-манифест и иконки (`apps/web/public`, собираются
`scripts/generate-pwa-icons.mjs` из лапы-лого). Воркер регистрирует само приложение
(`shared/lib/serviceWorker.ts`) и сразу активируется (`skipWaiting` + `clients.claim`): кэша нет,
поэтому обновление не ломает чтение. Вкладка видима — push не показывается (то же событие
приходит по SSE), кроме iOS: WebKit отзывает подписку, если на push не показать уведомление.
Типы воркера проверяет `tsconfig.sw.json` (среда WebWorker), в линт он не входит.

Ниже — целевая схема Фазы 4; `registerType: 'prompt'` и precache появятся вместе с кэшем.

## Service worker

`vite-plugin-pwa` в режиме `injectManifest` — генерируемый `generateSW` не потянет
логику скачивания глав.

```ts
// apps/web/vite.config.ts
VitePWA({
  strategies: 'injectManifest',
  srcDir: 'src/sw',
  filename: 'sw.ts',
  registerType: 'prompt', // не autoUpdate — см. ниже
  manifest: {/* ... */},
});
```

`registerType: 'prompt'`, а не `autoUpdate`: обновление SW посреди чтения главы
перезагружает страницу и теряет позицию. Показываем ненавязчивый тост «доступно
обновление» и применяем его, когда пользователь не в читалке.

## Стратегии кеширования

| Ресурс                                  | Стратегия                         | Параметры                           |
| --------------------------------------- | --------------------------------- | ----------------------------------- |
| App shell (JS, CSS, шрифты)             | Precache                          | Ревизии из манифеста сборки         |
| `/api/v1/sources`                       | StaleWhileRevalidate              | TTL 24 ч                            |
| `/api/v1/sources/*/titles` (каталог)    | NetworkFirst                      | Таймаут 3 с, TTL 15 мин, 50 записей |
| `/api/v1/titles/*` (детали, главы)      | StaleWhileRevalidate              | TTL 1 ч, 200 записей                |
| `/api/v1/img` — обложки                 | CacheFirst                        | TTL 30 дней, 500 записей, LRU       |
| `/api/v1/img` — страницы глав (онлайн)  | CacheFirst                        | TTL 7 дней, лимит по объёму         |
| `/api/v1/img` — страницы скачанных глав | **Отдельный кеш, без вытеснения** | `tanuki-offline-v1`                 |
| Навигация                               | NetworkFirst с офлайн-фолбэком    | `offline.html`                      |

Ключевой момент — **два раздельных кеша изображений**. Обычный кеш чтения живёт по LRU и
чистится браузером при нехватке места. Кеш скачанных глав чистится **только** по явному
действию пользователя. Иначе получится классический баг: скачал 20 глав перед перелётом,
полистал каталог, браузер вытеснил скачанное по LRU, в самолёте — пусто.

Различаются по заголовку `X-Tanuki-Offline: 1`, который клиент ставит при явной загрузке.

## Скачивание глав

```
Пользователь → «Скачать главу»
  1. UI пишет в Dexie downloads: { titleId, chapterId, status: 'queued' }
  2. Сообщение в SW через postMessage
  3. SW последовательно (не параллельно!) фетчит страницы с X-Tanuki-Offline: 1
  4. Прогресс шлётся обратно в UI через postMessage
  5. По завершении status: 'done', в Dexie кешируются метаданные главы
  6. Ошибка → status: 'failed', ретрай по кнопке
```

Последовательно, а не параллельно — намеренно. 200 одновременных запросов к источнику
это способ гарантированно получить бан по IP на прокси-сервере.

Очередь переживает закрытие вкладки: состояние в Dexie, докачка возобновляется при
следующем открытии. `navigator.storage.persist()` запрашивается при первом скачивании,
чтобы браузер не вытеснил данные.

Перед скачиванием проверяем квоту через `navigator.storage.estimate()` и честно
показываем «Глава ~45 МБ · свободно 1.2 ГБ».

## Манифест и установка

```json
{
  "name": "Tanuki — читалка манги",
  "short_name": "Tanuki",
  "description": "Манга, манхва и маньхуа из множества источников",
  "start_url": "/",
  "display": "standalone",
  "orientation": "any",
  "background_color": "#0a0a0b",
  "theme_color": "#0a0a0b",
  "lang": "ru",
  "categories": ["entertainment", "books"],
  "shortcuts": [
    { "name": "Продолжить чтение", "url": "/continue" },
    { "name": "Библиотека", "url": "/library" }
  ]
}
```

`orientation: "any"` обязательно — читалка должна работать и в ландшафте (режим
разворота). `display: "standalone"`, а не `fullscreen`: системная шторка нужна, чтобы
видеть время и заряд во время долгого чтения.

Промпт установки не показываем сразу. Ловим `beforeinstallprompt`, откладываем и
предлагаем установку после того, как пользователь дочитал вторую главу — в этот момент
ценность уже доказана.

## Ограничения, о которых надо знать заранее

- **iOS Safari.** PWA работает, но: квота хранилища жёстче, `navigator.storage.persist()`
  ведёт себя иначе, а данные могут быть удалены после 7 дней без открытия приложения
  (если PWA не установлена на домашний экран). Пользователей iOS надо прямо подталкивать
  к установке — иначе скачанные главы будут пропадать.
- **Wake lock** включается настройкой «Не гасить экран», по умолчанию выключен. Запрашивается
  только во время видимого чтения, освобождается при скрытии и выходе, восстанавливается при
  возвращении. Отсутствие поддержки и отказ браузера обрабатываются молча.
- **Fullscreen** доступен по кнопке или `F`, если браузер поддерживает API. Кнопка синхронизирована
  с внешним выходом, в том числе `Esc`; уход из читалки завершает её полный экран. Поддержка зависит
  от браузера и режима PWA.
- **Предзагрузка читалки** использует прежние URL изображений и кеши service worker, не добавляет
  главы в очередь скачивания. Скачанные главы читаются по синтетическим ключам `/offline/`;
  без сети очередь предзагрузки выключена, нескачанная следующая глава не открывается. Старый
  кеш ответа настроек получает новые поля с умолчаниями при чтении общей схемой контракта.
- **Квота** в Chrome обычно ~60% свободного места на диске, но полагаться на конкретное
  число нельзя, только на `estimate()`.
- Фоновая синхронизация (`Background Sync`) есть не везде — фолбэк на синхронизацию при
  открытии приложения.
