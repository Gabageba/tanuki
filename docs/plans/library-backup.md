# Резервная копия библиотеки

Статус: **Реализован** · 2026-10-23
Задача: `library-backup` · ветка `feat/library-backup` · песочница `/playground/library-backup`

## Зачем

В «Профиль → Данные» две из трёх строк блока «Импорт и экспорт» — заглушки:

- «Экспорт закладок» выбирает JSON/CSV и отвечает «Скоро будет доступно»;
- «Импорт закладок» не читает файл и показывает мок `MOCK_IMPORT_PREVIEW`;
- описание строки «Закладки, прогресс, оценки и история» врёт: оценок в приложении нет, истории
  не будет.

Библиотека и настройки живут только на сервере инстанса. Если инстанс закрылся, сменился или
человек хочет переехать на другой, забрать их не с чем. Фича для любого вошедшего пользователя
(гостей нет).

Удача:

- одной кнопкой скачивается файл, из которого на любом инстансе tanuki восстанавливается всё:
  папки, закладки, прогресс, статистика чтения и настройки;
- восстановление в непустую библиотеку ничего не теряет без спроса: по умолчанию только
  добавляет, а замену человек выбирает сам, видя, сколько всего она заденет;
- после восстановления видно, что добавилось, что поменялось и что пропущено и почему.

Остаётся как есть: импорт с источника (`ImportFromSourceRow`) — заглушкой до своего плана.

## Скоуп

- **Входит:**
  - свой формат резервной копии — JSON с версией формата;
  - выгрузка: кнопка сразу скачивает файл, без модалки;
  - восстановление: модалка «файл → сводка и выбор → готово»;
  - в копии — вся библиотека (папки, закладки, отметки прогресса, журнал прочитанных глав,
    активное время чтения) и все настройки (общие, читалки, порядок и выключенные источники);
  - правка текстов строк в профиле, удаление `ExportModal`, `EXPORT_FORMAT`, `MOCK_IMPORT_PREVIEW`.
- **Потом:**
  - импорт с источника — отдельным планом. Серверная запись закладок с учётом групп и папок из
    этой задачи (`BackupRestoreService`) переиспользуется им.
- **Не входит:**
  - формат Kotatsu — не делаем;
  - CSV: обратно без потерь не загружается (папки, их порядок, журнал), а сторонние трекеры
    принимают XML формата MAL, не CSV;
  - Mihon/Tachiyomi (protobuf, источники — хеши расширений);
  - отмена восстановления после записи;
  - автоматические и периодические копии.

## Сценарии

### 1. Создать резервную копию

1. Профиль → Данные → строка «Создать резервную копию», кнопка «Скачать копию».
2. Кнопка показывает `Loader`, пока сервер собирает файл.
3. Браузер скачивает `tanuki-backup-2026-10-23.json`. Тост не нужен — загрузку видно в браузере.
4. Без сети кнопка `disabled`: копию собирает сервер.

### 2. Восстановить из копии

1. Профиль → Данные → строка «Восстановить из копии», кнопка «Восстановить». Открывается модалка
   (тон `neutral`, иконка `UploadSimpleIcon`).
2. **Шаг «Файл».** `FileInput` (`accept=".json"`). Клиент читает файл и проверяет его схемой
   из контрактов; ошибка — под полем через `validate` формы: «Это не резервная копия tanuki»,
   «Копия сделана более новой версией tanuki», «Файл больше 20 МБ». Кнопка «Далее» (`type="submit"`)
   отправляет файл на сводку (`Loader` в кнопке).
3. **Шаг «Сводка».** Сверху — чья копия и когда: «Копия gabageba от 12 октября 2026 г.», под
   ней адрес инстанса. Ниже — что в ней и как ляжет:
   - закладки: новых N, уже в закладках в той же папке, в другой папке M, пропущено K (источника
     нет на этом инстансе);
   - папки: новых, совпавших по имени, сверх лимита (их тайтлы лягут в «В планах»);
   - отметки прогресса: новых, с разными отметками;
   - глав в статистике, настройки.

   Есть конфликты — кнопки «Отмена» и «Далее» к шагу «Вопросы». Конфликтов нет — на сводке
   флажок «Применить настройки из копии» и кнопки «Отмена» и «Восстановить» (`type="submit"`).
   Назад к файлу — стрелка в заголовке.

4. **Шаг «Вопросы»** — только если есть о чём спрашивать:
   - есть тайтлы в другой папке → «7 тайтлов уже в закладках, но в другой папке»: «Оставить
     мои» (по умолчанию) / «Взять из копии»;
   - есть расходящиеся отметки → «Где остановился: 5 отметок расходятся с вашими»: «Дальше
     прочитанное» (по умолчанию) / «Мой текущий» / «Из копии»;
   - флажок «Применить настройки из копии», по умолчанию выключен.

   Кнопки «Отмена» и «Восстановить» (`type="submit"`) — сразу пишет, без предупреждения. Назад к
   сводке — стрелка в заголовке.

5. **Шаг «Готово».** Тон `success`. Итог: добавлено закладок, перенесено в другие папки, создано
   папок, обновлено отметок, добавлено глав в статистику, применены ли настройки, пропущено (с
   причиной). Кнопки «Закрыть» и «Открыть закладки».
6. Закрытие модалки на любом шаге до «Восстановить» ничего не пишет.

### 3. Переезд на другой инстанс

То же, что 1 + 2: копия с одного инстанса загружается на другом. Тайтлы источников, которых там
нет, пропускаются и считаются в итоге; выключенные или скрытые настройкой 18+ — загружаются,
карточка покажет обычную «недоступна» (`BOOKMARK_AVAILABILITY`).

## Логика и правила

### Что в копии

| Часть                   | Откуда             | Примечание                                                         |
| ----------------------- | ------------------ | ------------------------------------------------------------------ |
| Папки                   | `bookmark_folders` | встроенные — по `builtIn`, свои — имя, иконка, цвет, флаг, порядок |
| Закладки                | `bookmarks`        | папка — ссылкой на папку копии, снимок, даты                       |
| Отметки прогресса       | `reading_progress` | вместе со снимком тайтла и `hiddenAt`                              |
| Журнал прочитанных глав | `chapter_reads`    | статистика                                                         |
| Активное время чтения   | `reading_activity` | статистика (сессии, час пик)                                       |
| Общие настройки         | `user_settings`    | все поля, **кроме `ageConfirmed`**                                 |
| Настройки читалки       | `reader_settings`  |                                                                    |
| Выключенные источники   | `disabled_sources` |                                                                    |
| Шапка                   | —                  | версия формата, дата выгрузки, логин, адрес инстанса               |

Не попадают: аккаунты источников (секреты), история поиска, уведомления, push-подписки,
устройства, аватар, скачанные главы (они в браузере), связи тайтлов `title_links` (общие для
инстанса, не личные). `ageConfirmed` не переносится: подтверждение возраста из чужого файла
обходило бы вопрос «вам есть 18?».

### Восстановление

Всё пишется одной транзакцией. Один пользователь — одно восстановление за раз (advisory lock по
`userId`), второе отвечает 409.

**Источники.** `sourceId`, которого нет в каталоге инстанса, — строка пропускается (закладка,
отметка, глава журнала), счётчик `skippedUnknownSource`. Выключенный, лежащий, скрытый 18+ —
загружается.

**Папки.**

- встроенная — сопоставляется по `builtIn`, её флаг и место не меняются;
- своя — по имени без учёта регистра (тот же ключ, что `bookmark_folders_user_name_lower_idx`):
  совпала — это та же папка, иконку, цвет и флаг не трогаем; нет — создаётся в конце, в порядке
  копии;
- если новых больше, чем осталось до `CUSTOM_BOOKMARK_FOLDERS_LIMIT`, лишние не создаются, их
  закладки ложатся во встроенную «В планах»; это видно и в сводке, и в итоге.

**Закладки** — по `titleKey` и группе подтверждённых совпадений:

| Что уже есть у пользователя                 | «Оставить мои»                    | «Взять из копии»                                        |
| ------------------------------------------- | --------------------------------- | ------------------------------------------------------- |
| ничего, и в группе ничего                   | добавить в папку копии            | то же                                                   |
| этот `titleKey` в той же папке              | ничего                            | ничего                                                  |
| этот `titleKey` в другой папке              | ничего                            | переносится вся группа                                  |
| подтверждённая копия группы, `titleKey` нет | строка добавляется в папку группы | строка добавляется, вся группа переезжает в папку копии |

Дубля карточки не бывает: строка, попавшая в группу, — ещё один источник той же закладки
(решение I1 из «Настройки источников»).

**Отметки прогресса** — по `titleKey`:

- отметки нет — пишется из копии при любом выборе;
- «Дальше прочитанное» — побеждает та, у которой больше `chapterNumber`, при равенстве — больше
  `pageIndex`; если у одной из сторон номера нет — свежий `updatedAt`;
- «Мой текущий» — не трогаем; «Из копии» — заменяем.

**Статистика** — всегда объединение, без вопроса: `chapter_reads` — `on conflict do nothing`
(PK `userId, chapterId`), дата прочтения из копии; `reading_activity` — по минуте, при совпадении
— большее число секунд.

**Настройки** — только с флажком:

- `user_settings` (кроме `ageConfirmed`) и `reader_settings` заменяются целиком;
- выключенные источники — заменяются для источников, известных инстансу; неизвестные отбрасываются;
- `sourceOrder` — порядок копии для известных источников, источники инстанса, которых в копии
  нет, встают в конец (как уже работает для новых источников);
- ключи подборок (`selectionsDisabledSections`, `selectionsSectionOrder`) неизвестных источников
  отбрасываются.

После восстановления фронт инвалидирует закладки, папки, прогресс, статистику, настройки и
источники; язык и тема применяются тем же путём, что при смене в настройках.

### Обратимость и тон

Отмены нет. По умолчанию восстановление только добавляет; что заменить, человек выбирает сам на
шаге «Вопросы». Модалка всё время `neutral`, итог — `success`. Предупреждения и совета скачать
текущую копию перед заменой нет — решено по макетам (★3, см. «Дизайн»).

## Данные и API

### Формат файла

`BackupSchema` (zod) в `packages/contracts/src/backup.ts` — общий для сервера и клиентской
проверки. Корень:

```ts
{
  format: 'tanuki-backup',      // константа BACKUP_FORMAT
  version: 1,                   // BACKUP_VERSION; больше поддерживаемого — отказ
  exportedAt: '2026-10-23T10:00:00Z',
  origin: 'https://tanuki.example.com',
  username: 'gabageba',
  settings: { user: {...}, sourceOrder: string[] | null, reader: {...} | null, disabledSources: string[] },
  folders: [{ key, builtIn, name, icon, color, trackUpdates, position }],
  bookmarks: [{ titleId, folderKey, name, coverUrl, contentRating, type,
                visitedAt, createdAt, updatedAt }],
  progress: [{ titleKey, sourceId, chapterId, chapterVolume, chapterNumber, chapterTitle,
               branchId, pageIndex, titleId, titleName, coverUrl, contentRating, type,
               hiddenAt, updatedAt }],
  chapterReads: [{ chapterId, sourceId, titleKey, chapterVolume, chapterNumber, tags, readAt }],
  readingActivity: [{ minute, seconds }],
}
```

`folderKey` — id папки на исходном инстансе, нужен только чтобы связать закладку с папкой внутри
файла. Даты — `YYYY-MM-DDTHH:MM:SSZ`. Значения enum'ов — как в контрактах, без преобразований.

### Эндпоинты (`apps/api/src/backup`, модуль `BackupModule`)

| Метод и путь                  | Тело / ответ                                                                                                        |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `GET /api/v1/backup`          | файл JSON, `Content-Disposition: attachment; filename="tanuki-backup-YYYY-MM-DD.json"`                              |
| `POST /api/v1/backup/preview` | тело — `Backup`; ответ — `BackupPreview`: шапка и счётчики по каждой части, флаги «есть конфликт папок / прогресса» |
| `POST /api/v1/backup/restore` | тело — `{ backup, folderPolicy, progressPolicy, applySettings }`; ответ — `BackupRestoreResult` (счётчики итога)    |

- лимит тела 20 МБ на этих двух маршрутах (`bodyLimit`, как у аватара), общий — не трогаем;
- файл отправляется дважды (сводка и запись): сервер ничего не хранит между шагами; при 20 МБ
  это терпимо — см. «Открытые вопросы»;
- коды ошибок — новые значения общего enum ошибок: `backupVersionUnsupported`,
  `restoreInProgress` (409); невалидное тело — обычная ошибка валидации.

### Код

- `BackupExportService` — собирает файл из таблиц; `BackupRestoreService` — `preview` и `restore`
  на одном расчёте плана («что куда ляжет»), `preview` его только считает. Запись закладок в
  группу — через `TitleLinksService.listConfirmedGroup`, как в `BookmarksService`.
- Тесты: сопоставление папок (имя без регистра, лимит → «В планах»), четыре строки таблицы
  закладок × две политики, три политики прогресса, неизвестный источник, объединение журнала,
  настройки (`ageConfirmed` не пишется, порядок источников), 409 при параллельном восстановлении.

## Крайние случаи

| Случай                                          | Что видит пользователь                                               |
| ----------------------------------------------- | -------------------------------------------------------------------- |
| Пустая библиотека при выгрузке                  | файл скачивается — в нём настройки и пустые списки                   |
| Без сети                                        | «Скачать копию» и «Восстановить» `disabled`                          |
| Не JSON / чужой JSON                            | ошибка под полем «Это не резервная копия tanuki»                     |
| Версия новее                                    | «Копия сделана более новой версией tanuki»                           |
| Файл > 20 МБ                                    | «Файл больше 20 МБ» под полем, на сервер не уходит                   |
| В копии нет ничего нового                       | сводка: «Всё из копии уже есть»; «Восстановить» остаётся (настройки) |
| Нет конфликтов                                  | вопросов про папки и прогресс нет, только флажок настроек            |
| Все тайтлы с неизвестных источников             | сводка показывает только «пропущено», закладки не добавятся          |
| Своих папок сверх лимита                        | в сводке и итоге: «N папок не поместились — тайтлы в „В планах“»     |
| Копия чужого аккаунта / другого инстанса        | разрешено, в шапке сводки видно чей и откуда                         |
| Повторное восстановление того же файла          | «Всё из копии уже есть» — ничего не задваивается                     |
| Второе восстановление параллельно (две вкладки) | тост глобального обработчика об ошибке, модалка остаётся на сводке   |
| Ошибка сервера на сводке / записи               | тост глобального обработчика, шаг не меняется, можно повторить       |
| Длинный логин, длинный адрес инстанса           | переносятся, не обрезаются                                           |

## Дизайн

**Где живёт.** «Профиль → Данные», блок `GroupedList` «Импорт и экспорт» — тот же блок, порядок
строк тот же:

| Строка                  | Иконка               | Описание                                            | Кнопка                                 |
| ----------------------- | -------------------- | --------------------------------------------------- | -------------------------------------- |
| Создать резервную копию | `DownloadSimpleIcon` | Закладки, прогресс, статистика и настройки          | «Скачать копию» (`DownloadSimpleIcon`) |
| Восстановить из копии   | `UploadSimpleIcon`   | Добавляет к библиотеке, ничего не удаляя без спроса | «Восстановить» (`UploadSimpleIcon`)    |
| Импорт из источника     | без изменений        | без изменений                                       | без изменений                          |

**Выбрано по макетам** (`/playground/library-backup`) — **R1 + F1 + T2 + H1 + S1 + Q1a + D1 + ★3**,
подробно — [Резервная копия библиотеки](../11-ui-decisions.md#резервная-копия-библиотеки):
строки профиля по таблице выше (R1, без даты последней копии); «Файл» — `FileInput` с
пояснением (F1); на внутренних шагах — стрелка назад (T2); сводка — чья копия главной фразой (H1)
и счётчики строками `GroupedList` (S1); вопросы — `Radio.Card`, число в заголовке вопроса (Q1a),
своим шагом после сводки (★3); «Готово» — теми же строками, что сводка (D1).

**Модалка восстановления** — `ToneModal`, до четырёх шагов в одной модалке (как
`ImportFromSourceModal`): файл → сводка → вопросы (только при конфликтах) → готово; стрелка
«назад» в заголовке на сводке и вопросах. Тон: `neutral`, на «Готово» — `success`. Иконка —
`UploadSimpleIcon`, на «Готово» — `CheckCircleIcon`. Тексты: главное в 14, пояснения `<Text c="dimmed" fz={13}>`. Числа сводки и
итога — `ff="monospace"`, дата копии — словами (`formatDate`), «г.» без точки после.

Мобилка и десктоп — одна раскладка; модалка на телефоне — в ширину экрана и по высоте содержимого,
как остальные модалки приложения.

**Терминология**

| Понятие                                  | В UI                                    |
| ---------------------------------------- | --------------------------------------- |
| файл выгрузки                            | резервная копия, «копия»                |
| выгрузить                                | создать резервную копию / скачать копию |
| загрузить файл обратно                   | восстановить из копии                   |
| закладки + папки + прогресс + статистика | библиотека                              |
| отметка прогресса                        | «где остановился»                       |

Слова «экспорт» и «импорт» для этой фичи не используются — остаются у «Импорта из источника» и
в подписи блока.

**Референсы:** «Резервная копия» в Kotatsu и Mihon. **Антиреференс:** выбор формата без
причины (текущая заглушка), замена данных без вопроса (заменяет только то, что выбрано на шаге
«Вопросы»).

## Вопросы к макетам

1. **Сводка.** Как подать счётчики: `ProgressList` по частям, `GroupedList` строками «Закладки /
   Папки / Прогресс / Статистика / Настройки» с числами справа, или компактные строки текста.
   Где шапка «чья копия и откуда». — **S1 + H1:** строки `GroupedList`, новых — справа; шапка —
   главной фразой над ними.
2. **Вопросы о конфликтах.** `Radio.Card` строками (как выбор источника и темы), `SegmentedControl`
   или `Select`; как показать, сколько тайтлов/отметок вопрос затронет («12 тайтлов в других
   папках»). — **Q1a + ★3:** `Radio.Card`, число в заголовке вопроса, вопросы своим шагом.
3. **Предупреждение при `warning`.** Где и как появляется совет скачать копию: строкой текста с
   кнопкой, отдельной строкой `GroupedList`, кнопкой в `ModalButtonsLayout`. — **Нигде:**
   предупреждения и совета нет, тон `warning` не используется.
4. **Шаг «Готово».** Список счётчиков в том же виде, что сводка, или короче; как показать
   пропущенное с причинами. — **D1:** те же строки, пропущенное — своей строкой с причиной.
5. **Шаг «Файл».** Просто `FileInput` или зона перетаскивания (`Dropzone`), есть ли под ним
   пояснение, что такое копия. — **F1:** `FileInput` с пояснением.
6. **Строка «Создать резервную копию».** Нужна ли рядом дата последней копии (тогда её надо
   хранить — сейчас не планируется). — **R1:** без даты.

### Чем реализация отличается от плана

- **Закладка в файле без `titleKey` и `sourceId`** — сервер выводит их из `titleId`, иначе файл
  мог бы противоречить сам себе. У отметок и журнала они остались: `titleId` у старых отметок
  null, а в журнале его нет вовсе.
- **Защита img-прокси от SSRF** — в плане её не было. Обложки из файла пишутся как есть, и
  подписанный `/img` ходил бы по любому адресу из подделанной копии, в том числе во внутреннюю
  сеть. Теперь прокси ходит только по `http(s)` на публичные адреса (`img-proxy/upstream-guard.ts`).
- **Настройки 18+ из копии** применяются, только если возраст на этом инстансе уже подтверждён.
  План исключал из копии `ageConfirmed`, но сервер открывает 18+ по одному `showAdultSources` —
  флажок «Применить настройки» обходил бы вопрос «вам есть 18?».
- **Выключенная в копии история поиска стирает накопленную** — как при выключении в настройках.
- **После записи перезапрашивается весь кеш**, а не перечисленные запросы: восстановление задевает
  почти все данные пользователя, и список ключей легко разошёлся бы с ними. Тема и язык
  применяются общим `shared/lib/applyUserSettings` — тем же, что при входе (`UserSettingsSync`).
- **Лимит тела** — 20 МБ плюс 1 МБ запаса на поля запроса вокруг файла, хуком `onRoute` только на
  `/backup/*`.
- Двойная отправка файла осталась: копия на 2,8 МБ (60 000 минут чтения) проходит сводку без
  заметной задержки.

## Открытые вопросы

- Двойная отправка файла (сводка + запись). На копии в 2,8 МБ незаметна; если на реальных больших
  копиях это станет заметно — хранить разобранный файл на сервере по токену минут 15.

## Отвергнутые идеи

- **CSV** — не восстанавливается без потерь, сторонним трекерам не подходит.
- **Модалка выгрузки с выбором состава или формата** — выбирать нечего, кнопка сразу качает файл.
- **Отмена восстановления в тосте / автокопия перед восстановлением** — сложно и редко нужно.
- **Предупреждение и совет скачать текущую копию при заменяющем выборе** — отвергнуты по макетам
  (W1–W4, шаг-предупреждение ★1): замену человек и так выбирает сам отдельным шагом.
- **Список тайтлов с чекбоксами перед восстановлением** — копия переносит библиотеку целиком,
  поштучный выбор — для импорта с источника.
- **Папки сверх лимита — ошибка** — восстановление не должно упираться в лимит; тайтлы ложатся в
  «В планах».
- **Своя папка из копии всегда новой, с суффиксом** — дробит библиотеку при повторном
  восстановлении.
- **Перенос `title_links` и `ageConfirmed`** — связи общие для инстанса, подтверждение возраста
  личное.
