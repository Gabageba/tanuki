# Единая карточка тайтла

Статус: **Реализован** · 2026-11-03

Задача: `unified-title-card` · ветка `feat/title-cards`

## Утверждённая архитектура

Один готовый компонент сущности `entities/title/card/TitleCard/TitleCard.tsx` с React-слотами
`meta` / `footer` и массивом `actions`. Кнопка и меню действий создаются внутри карточки.
Общими стали переход, обложка, название,
описание, маркеры, скрытие 18+, точка новых глав и оформление недоступности.
Низкоуровневые `CoverImage` / `TextSkeleton` остаются в shared.

`TitleCardData` — модель отображения, а не новый серверный контракт. Обязательны
`id`, `name`, `coverUrl`, `sourceId`, `contentRating`; описание, оценка, папка,
признак обновлений и доступность передаются там, где есть соответствующие данные.
Наличие `hasNewChapters` резервирует место под точку даже при `false`; недоступность
скрывает её и приглушает название. Размытие 18+ вычисляется внутри по настройкам.

Уточнение 2026-11-06: для `BookmarkCard` выбрана и реализована
[оранжевая мета N18](../11-ui-decisions.md#новые-главы-в-карточке-закладки-n18).
Закладка больше не передаёт `hasNewChapters` в общую карточку; признак обновлений
обрабатывает `BookmarkMetaLine`, окрашивая прогресс при доступном источнике.
Общий механизм точки сохранён для архивных макетов.

Публичный API:

- `data` — общие данные и состояния отображения;
- `viewMode`, `listSize` — плитка / список, обложка 120 / 84 px;
- `showSource` — лента источника на плитке;
- `meta`, `footer` — содержимое конкретного сценария;
- `actions` — массив действий с подписью, иконкой, обработчиком либо ссылкой и необязательной группой.

Плитка и список — отдельные компоненты с явным switch в `TitleCard`. Внутренний
контекст содержит только `viewMode` / `listSize`. `useTitleCardLayout` используют
обложка, название и метаданные; обёртки не сравнивают виды. Объекты `grid` / `list`,
внешние слоты имени, описания, декораций и оверлея удалены. Compound API не нужен:
структура общая и не собирается заново у каждого потребителя.

## Композиции

- `SourceTitleCard` (`entities/source/components/SourceTitleCard/`) — данные `Title`
  каталога, поиска, подборок и совпадений;
  `SourceTitleMeta` и `SourceTitleFooter` содержат их собственные метаданные.
- `BookmarkCard` — снимок закладки, доступность, признак обновлений, прогресс и меню.
- `ContinueReadingCard` — данные истории чтения, номер главы, время и меню удаления.
- `NewChapterRow` — компактный список, папка на обложке и сведения о новых главах.

`TitleCardDecorations` находится внутри общей обложки и переиспользует маркеры entities.
Уточнение 2026-11-04: после сравнения вариантов сохранена прежняя метка папки K4a
на обложке и в плитке, и в списке; перенос к названию отменён.
Оценки обоих видов используют общий `TitleScoreMeta`.
Скрытие 18+ и недоступность используют подложку цвета фона с непрозрачностью 85%,
как у недоступных источников; `HiddenCoverOverlay` общий с превью настроек.
Отдельные `BookmarkTitle`, `BookmarkCover`, `TitleListMeta` и прежний shared-конструктор
удалены. Для архивных макетов главной отдельная обложка — локальный `MockTitleCardImage`.

## Скелетон

`TitleCardSkeleton` выбирает собственные лёгкие виды. Из готовой карточки не импортируются
изображение, имя, оверлеи или маркеры. Обложка — `Skeleton`, имя — `TextSkeleton` с числом
строк по раскладке. У подробного списка `withDescription` добавляет четыре строки описания
и оставляет одну строку имени; иначе имя занимает две строки. Снаружи — слоты плейсхолдеров
`meta` / `footer` и флаг `withActions`: скелетон действия рисуется внутри общего компонента.
Кнопка общего `TitleCardActions` и её скелетон используют один `TITLE_CARD_ACTION_SIZE`.
Корень `inert` / `aria-hidden`, ссылок нет. Используется тот же небольшой
контекст раскладки, чтобы метаданные сами выбирали вид своего плейсхолдера.

## Скоуп и отличия

Пользователь утвердил перенос общей анатомии внутрь сущности: название и описание
теперь общие, прежние внешние слоты и переопределения видов больше не нужны.
Внешний вид и состав данных приложения сохраняются. API, серверные DTO, запросы,
сетки, ленты, настройки и механизмы загрузки не меняются. Коммит и PR — отдельно.
