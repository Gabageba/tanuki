# Общие тосты проекта

Статус: **Дизайн выбран** · 2026-11-10
Задача: `global-toasts` · ветка `master` · песочница `/playground/global-toasts`

## Зачем

Объединить внешний вид, тексты и поведение всех тостов: ошибок, результатов действий,
отмены, событий из ленты уведомлений и предложений PWA. Правила действуют для гостей,
пользователей и администрации; доступность самого действия определяется существующими правами.

Сейчас `main.tsx` монтирует `<Notifications />` из `@mantine/notifications`, а вызывающий код
сам выбирает цвет, содержание и время. `entities/notification/toasts.ts` отдельно ограничивает
число тостов событий тремя; остальные вызовы в этот лимит не входят. Для отмены есть
`shared/ui/UndoToastMessage.tsx`, для PWA — `features/pwa/PwaOfferMessage.tsx`.

Удача: все сценарии используют одну систему, понятные сообщения не дублируются, кнопка
возврата не пропадает из-за постороннего события, а фоновые сообщения не мешают чтению.
По внешнему виду и тексту понятно, что произошло и доступно ли действие.

## Скоуп

- **Входит:** общий вид и размещение, смысловые тона, тексты, таймеры, общий лимит,
  очередь, объединение повторов, доступность с клавиатуры, правила для читалки,
  перевод всех существующих рабочих вызовов и их историй на общую систему.
- **Потом:** новые сценарии используют готовую систему; отдельный минимальный выпуск
  только для ошибок или только для оформления не выделяем.
- **Не входит:** новая лента или история тостов, изменение Web Push, новые категории
  уведомлений, новые настройки пользователя, API, серверное хранение и изменения парсеров.
  Тосты не становятся индикатором загрузки страницы или журналом выполнения операции.

Подтверждение успеха показывается, когда результат неочевиден. Изменившийся переключатель,
появившаяся закладка или обновлённый аватар сами подтверждают действие; универсального
«Сохранено» после каждой мутации нет. Отдельный тост с отменой нужен и при видимом результате.

## Сценарии

1. **Неочевидный результат.** Пользователь копирует ссылку в меню тайтла → одна строка
   «Ссылка скопирована» → тост закрывается через 5 с или крестиком.
2. **Ошибка запроса.** Загрузка или сохранение окончательно завершается ошибкой после
   существующей политики повторов → глобальный обработчик показывает тост на 10 с.
   Несколько чтений, упавших из-за одного сбоя сервера, дают одно сообщение;
   ошибки разных действий сохраняют собственный контекст.
3. **Возврат закладки.** «Убрать из закладок» → изменение по текущей логике и тост
   «Убрано из закладок» с кнопкой «Вернуть закладку» на 10 с → нажатие закрывает тост
   и запускает единственный запрос возврата. Успех возвращает данные без дополнительного
   подтверждения. Сбой показывает отдельный тост ошибки; исходный тост не восстанавливается,
   кнопки повторного возврата в нём нет.
4. **Возврат на главную.** Удаление карточки из «Продолжить чтение» → тост с кнопкой
   «Вернуть тайтл» → тот же порядок закрытия и обработки ошибки, что у закладки.
   Прогресс чтения не сбрасывается.
5. **Событие из ленты.** SSE сообщает об источнике, аккаунте или администрировании →
   предметная иконка, заголовок и необходимое пояснение → клик по карточке открывает
   существующую цель и убирает запись из ленты по действующим правилам.
   Крестик закрывает только тост и не считает событие прочитанным.
6. **Во время чтения.** Результаты действий в читалке, её ошибки и события безопасности
   показываются сразу. Остальные фоновые события ждут выхода из читалки.
   После выхода каждое актуальное событие показывается отдельно по очереди, без сводки.
7. **PWA.** Доступно обновление или выполнены условия предложения установки → постоянный
   тост с явной кнопкой. В читалке предложение не показывается. Обновление имеет приоритет
   над установкой по текущей логике. При нехватке места PWA временно уступает его,
   оставаясь доступным через меню аккаунта; это не отказ пользователя.

## Логика и правила

### Единая точка управления

Один хост тостов работает на уровне приложения, включая страницы входа и читалку вне
основного `Layout`. Все производители проходят через общий механизм; прямые вызовы
`notifications.show/hide` остаются только внутри него, если используется транспорт Mantine.
Отдельный `visibleToastIds` в `entities/notification/toasts.ts` больше не управляет лимитом.

Основа UI — Mantine. На реализации проверить возможности установленного пакета по локальным
типам и коду: лимит Mantine сам по себе ставит лишние сообщения в очередь и не реализует
все согласованные правила вытеснения. Логику очереди и таймеров держит один владелец;
нельзя параллельно расходовать время в очереди приложения и во внутренней очереди Mantine.

Общий механизм знает о сообщении, времени, приоритете и доступных слотах, но не о закладках,
SSE и воркере. Предметные компоненты сохраняют свои действия и состояние рядом с потребителем.
Композиция — через `ReactNode`-слоты; конструктора UI из перечня типов действий не вводим.

### Тон и время

Существующий `NOTIFICATION_TONE` переносится в общий слой как единый `FEEDBACK_TONE`;
его потребители, включая ленту, переходят на общий тип без копии перечисления в `entities`.
Тип выводится через `EnumLiteralsOf`. Это клиентское понятие, контракты API не меняются.

```ts
export const FEEDBACK_TONE = {
  ACCENT: 'accent',
  DANGER: 'danger',
  WARNING: 'warning',
  SUCCESS: 'success',
  NEUTRAL: 'neutral',
} as const;
```

| Смысл                                            | Время видимого показа                      |
| ------------------------------------------------ | ------------------------------------------ |
| Обычный результат, успех, нейтральное сообщение  | 5 с                                        |
| Предупреждение                                   | 8 с                                        |
| Ошибка, событие безопасности                     | 10 с                                       |
| Возможность вернуть действие, независимо от тона | 10 с                                       |
| Установка и обновление PWA                       | До явного закрытия или утраты актуальности |

Тон и приоритет — разные свойства: красная ошибка обычного запроса не становится
событием безопасности. Для безопасности сохраняется предметная классификация из
`getNotificationTone` / `NOTIFICATION_TYPE`, а не проверка текста или цвета.

Таймер запускается с первого реального показа, а не с поступления в очередь. Наведение
мышью и фокус внутри тоста приостанавливают отсчёт. Для скрытой вкладки отсчёт также
приостанавливается, чтобы кнопка отмены не сгорела вне поля зрения. После паузы идёт остаток
времени; повтор одного сообщения не продлевает его бесконечно.
Отсутствие мыши на телефоне не мешает нажать действие в пределах тех же 10 с.

### Лимит, вытеснение и очередь

- Общий максимум — **три видимых тоста** на десктопе и телефоне, включая ошибки, PWA и отмены.
- Обычный новый тост может вытеснить самый старый обычный видимый тост. Тост с фокусом
  внутри временно защищён от вытеснения.
- Тосты с отменой и события безопасности не вытесняются обычными сообщениями.
- Постоянное предложение PWA при нехватке места скрывается программно, освобождая слот.
  Действие остаётся в меню; после освобождения места предложение может вернуться,
  если по-прежнему актуально и не было явно отклонено.
- Если вытеснить нечего, новые сообщения ждут. Отмены и безопасность имеют приоритет
  перед обычной очередью; внутри одного приоритета порядок поступления сохраняется.
  PWA занимает место после ожидающих временных сообщений.
- Закрытие, истечение времени, запуск действия или отмена актуальности освобождают слот.
  Очередь не перезапускает уже завершённые действия.
- Временно скрыть, окончательно убрать как неактуальный и явно закрыть крестиком — разные
  причины. Только явное закрытие предложения PWA вызывает существующий `onDismiss`.

После читалки отложенные события занимают свободные места по очереди. Их нельзя разом
передать в обычное вытеснение, показав лишь последние три: каждое получает свой показ.
Если во время ожидания запись обновилась — в очереди остаётся последняя версия;
если удалена или открыта другим способом — её отложенный тост снимается.

Ожидающие сообщения живут в памяти текущей вкладки. Перезагрузка не воспроизводит старую
очередь; важные события остаются в серверной ленте. При выходе из аккаунта очищаются
его видимые и ожидающие сообщения и обработчики действий; результат самого выхода или
перехода по ссылке из письма может показать новый тост уже в гостевом контексте.

### Повторы

Объединение определяется смысловым ключом, а не совпадением переведённого текста:

- SSE: идентификатор записи `notification-${item.id}`, повтор обновляет ту же запись.
- Общая недоступность сервера: чтения объединяются по причине сбоя; для ошибки конкретного
  источника в ключ входит источник. Ошибки разных источников не склеиваются.
- Запись данных и локальные операции: действие, объект и попытка. Два неудачных сохранения
  разных объектов дают два сообщения, даже если текст одинаков.
- Отмена: отдельный идентификатор успешного действия. Несколько удалённых закладок сохраняют
  отдельные кнопки; одна отмена не подменяет другую.
- PWA: тип предложения; для обновления учитывается актуальный ожидающий воркер.

Пока сообщение видно или ждёт показа, его повтор не создаёт вторую запись. Для пачки
ошибок чтения после ручного закрытия применяется короткое окно подавления — **2 с**
от последнего принятого сообщения этой пачки. Новое явное действие пользователя — новая
попытка, его ошибка не скрывается этим окном. Последующий независимый сбой снова показывается.

### Ошибки и существующие исключения

Сохраняются правила `app/Providers/QueryClientProvider.tsx` и `shared/api/errorMeta.ts`:

- ошибки форм, отмеченные `SILENT_ERROR_META`, объясняются полями без общего тоста;
- `silentNextPageError` сохраняет локальное объяснение сбоя подгрузки;
- без сети сетевые тосты подавляются: работают индикация офлайна и существующие состояния;
- исключения для закрытого источника и скрытого контента 18+ остаются;
- главный сбой страницы может давать и `QueryError`, и один тост;
- сбой блока объясняет глобальный тост, сам блок показывает пустое состояние;
- истёкшая сессия обрабатывается один раз: выход, переход ко входу и одно сообщение;
- отменённый пользователем запрос или закрытый системный лист «Поделиться» не являются ошибкой.

Сообщение `ApiRequestError.message` уже переведено сервером и выводится как есть.
Для непредвиденной клиентской ошибки — существующий понятный запасной текст, без стека,
технических подробностей и сырой ошибки парсера. Заголовок называет действие, если без него
неясно, что не получилось; бессодержательное «Ошибка» не добавляется к каждому сообщению.
Общий тост не получает автоматическую кнопку повторной отправки мутации.

После клика по возврату исходный тост удалён до начала запроса: повторно нажать его нельзя.
Сбой возврата обрабатывает ровно один путь — общий обработчик мутации или общий вызов
для локального `catch`; второй тост той же ошибки не создаётся. Применяются обычные правила
офлайна. Восстановление не считается успешным до успешного ответа.

### Читалка и скрытая вкладка

Результаты непосредственных действий и ошибки читалки, а также безопасность показываются
в читалке. События источников, парсеров и администрирования ждут выхода.
Это меняет текущее правило, при котором все важные SSE-события показываются поверх чтения.
PWA по-прежнему ждёт выхода. Ошибки чтения не откладываются только потому, что они связаны
с источником: это результат текущего запроса, а не фоновое SSE-событие.

Новые главы не получают тоста — по текущему решению меняется лента и индикатор.
SSE-события, пришедшие в невидимую вкладку, не пополняют очередь тостов: для этого сценария
остаются действующие push и лента. Исключение WebKit для push не меняется.

## Данные и API

Новых эндпоинтов, полей БД, серверных enum и изменений `packages/parsers` нет.
Используются существующие `NotificationItem`, события SSE и операции возврата:
`POST /bookmarks/restore`, `DELETE /titles/:titleId/progress/hidden`.

Клиентская запись очереди содержит идентификатор, смысловой ключ повторов, контекст
владельца, тон, заголовок при необходимости, содержание и слоты, время и остаток показа,
признак защиты от вытеснения и допустимость показа в текущем контексте.
Состояния: ожидание → показ ↔ пауза → закрытие; программно скрытое PWA возвращается
в ожидание, потерявшее актуальность сообщение окончательно удаляется.
Снимок данных для возврата остаётся у текущей предметной операции.

Общая система не сохраняет очередь и функции действий в `localStorage`, IndexedDB или API.
Существующие PWA-данные об отказе от установки и условиях предложения сохраняются по
`shared/lib/appInstall` и `shared/lib/serviceWorker.ts`; отказ не записывается при вытеснении.
Ничего нового другим пользователям не показывается. Настройки push не отключают результаты
действий или ошибки; существующие правила отбора SSE-событий сохраняются.

| Длинное название, английский текст                 | Перенос текста, действия и крестик остаются доступны                        |

| Модалка, клавиатура телефона, горизонтальный экран | Тост не перекрывает обязательные действия и учитывает доступную область     |

## Дизайн

Уточнено 2026-11-10: **A1 + T5 + D5a + S2 + I1 + C1** — тонкая цветная полоса,
отступы 16 px, все заголовки весом 600, отдельный футер с кнопкой 30 px и текстом 14 px,
стек 420 px с интервалом 12 px, подсветка события без стрелки и центрирование простого сообщения.
D5a использует `compact-sm` с минимальной высотой 30 px и переносом длинной подписи;
встроенные размеры D5c–D5e сохранены как альтернативы.
Итог и все прежние варианты сохранены в `/playground/global-toasts`;
подробности — [в решении по макетам](../11-ui-decisions.md#общие-тосты-проекта).
В «Итоге» сразу открыта галерея всех тостов, ниже — интерактивный стек на общем состоянии
десктопа и телефона. Перенос в рабочую систему — следующий этап.

- На десктопе — снизу справа. На телефоне — снизу над существующей навигацией.
  В читалке и на страницах входа без нижней навигации учитывается фактическая раскладка,
  `safe-area` и открытая клавиатура; пустой отступ под отсутствующую панель не резервируется.
- Общая спокойная карточка. Тон выражают иконка и небольшой цветовой акцент;
  сплошная яркая заливка по смыслу не используется. Все пять тонов совместимы с темой.
- Короткий результат — одно сообщение. Заголовок и пояснение появляются, если добавляют
  смысл: «Не удалось сохранить» / «Нет соединения с сервером».
- Обычным сообщениям — стандартная смысловая иконка; событиям — предметная иконка из
  существующего `getNotificationIcon`, PWA — иконка установки или обновления.
  Все иконки из `@phosphor-icons/react`.
- Цвета берутся из Mantine и существующей палитры; успех, предупреждение и опасность
  используют общие семантические цвета, без новых независимых шкал в компонентах.
- Текст — Golos Text, 14; пояснение можно отличать цветом. Размер 13 не используется:
  по `AGENTS.md` он отведён пояснениям модалок. Числа внутри фраз остаются частью речи.
- Событие из ленты открывается всей карточкой, доступно с клавиатуры. Обычный тост
  не имеет ложного `cursor: pointer`. Кнопка и крестик не вызывают переход карточки.
- У отмены и PWA — явная кнопка с иконкой. Подпись называет объект действия.
  Крестик с переведённым `aria-label` есть у всех тостов; это не действие отмены.
- Появление не перехватывает фокус. Для обычных сообщений — ненавязчивое объявление
  скринридером, для ошибки и безопасности — своевременное объявление; повтор не озвучивается
  заново без изменения смысла. Анимация учитывает уменьшение движения в системе.

| Понятие                       | Как называем в UI                                                 |
| ----------------------------- | ----------------------------------------------------------------- |
| Краткое подтверждение         | Конкретный результат: «Ссылка скопирована», «Пароль изменён»      |
| Возврат закладки              | «Вернуть закладку»                                                |
| Возврат в «Продолжить чтение» | «Вернуть тайтл»                                                   |
| Обновление PWA                | «Доступно обновление», «Обновить приложение»                      |
| Установка PWA                 | «Установить Tanuki», «Установить приложение»                      |
| Ошибка действия               | «Не удалось …» с понятным объектом; пояснение сервера при наличии |

Слово «тост» остаётся термином разработки и не становится названием раздела интерфейса.
Рабочие тексты проходят через `react-i18next`; существующие значения переиспользуются.
Новые ключи плоские, по русскому исходнику; целая фраза переводится одним ключом.
Для новых кнопок возврата проверить наличие подходящих значений в `ru.json` перед добавлением.
Тексты макетов и названия историй — русские литералы вне словарей.

Референсы — нынешние событийные тосты, `UndoToastMessage` и `PwaOfferMessage` как реальные
сценарии. Внешних обязательных референсов нет. Антиреференсы: тост после каждого сохранения,
яркая заливка целой карточки и очередь одинаковых ошибок на весь экран.

## Вопросы к макетам

Все шесть вопросов закрыты выбранным дизайном
[A1 + T5 + D5a + S2 + I1 + C1](../11-ui-decisions.md#общие-тосты-проекта):

1. **Небольшой акцент — A1.** Подложка иконки и тонкая цветная полоса на нейтральной
   карточке; общий вид применён ко всем пяти тонам.
2. **Однострочный и подробный тост — T5 + C1.** Отступы 16 px, все заголовки — 600,
   весь текст 14 px; пояснение обычного начертания и приглушено. Короткий результат не получает
   обязательную вторую строку. Без пояснения и действия текст, иконка и крестик центрируются
   по вертикали; подробные сообщения сохраняют верхнее выравнивание. Длинные тексты RU/EN
   переносятся целиком и открыты в итоговой галерее.
3. **Кнопка действия — D5a.** Футер отделён тонким разделителем, нейтральная кнопка справа.
   Основа — Mantine `compact-sm`: минимальная высота 30 px, текст 14 px, уменьшенные боковые
   отступы и перенос длинной подписи. Обе отмены и предложения PWA используют одну оболочку;
   у кнопки предметная подпись и иконка.
4. **Стек из трёх — S2.** Ширина 420 px и интервал 12 px; на телефоне доступная ширина
   с полями по 12 px над навигацией. Старые сообщения выше, новые снизу; появление со сдвигом
   и затуханием учитывает уменьшение движения. Очередь и вытеснение показаны на общем состоянии
   двух рамок. Проверены обе темы и ширины 320–1440 px.
5. **Совместимость с оверлеями — O1–O3 и итог.** Тост выше слоя оверлея и внутри его области
   фокуса. При малой высоте форма получает прокрутку над ним; `visualViewport` и безопасные
   отступы удерживают сообщение в доступной области. Проверены модалка, drawer и область
   высотой 360 px; у входа и читалки нет отступа под отсутствующую навигацию.
6. **Интерактивность — I1.** Вся карточка события кликабельна, при наведении подсвечивается,
   при клавиатурном фокусе получает контур; постоянной стрелки нет. Обычные сообщения
   не выглядят кликабельными, крестик и отдельная кнопка не вызывают переход.

Песочница показывает все типы и смешанные стеки в обеих темах, а также демонстрации
повторов, защищённых отмен и показа очереди после читалки. В «Итоге» все примеры открыты
сразу; интерактивный стек ниже сохраняет общий лимит в три. Она не меняет рабочее приложение.

## Этапы реализации

1. **Основа без макетов.** Спроектировать общий механизм в `shared/lib/toasts/`:
   модели, очередь, таймеры, причины закрытия и объединение повторов. Перенести общее
   понятие тона в этот слой. Предусмотреть детерминированное время в тестах.
   Контракты, API и парсеры не требуют этапа изменений.
2. **UI по выбранному макету.** Общая оболочка и хост в `shared/ui/Toast/`, подключение
   в `main.tsx`, сведения о текущей раскладке и читалке через слой `app`.
   Не импортировать маршруты и предметную логику в универсальный механизм очереди.
   Предметные действия передаются композиционно.
3. **Ошибки.** `app/Providers/QueryClientProvider.tsx`, `shared/api/errorMeta.ts`:
   сохранить все исключения, передавать контекст смыслового объединения,
   исключить двойную обработку. Не объединять все ошибки только по `API_ERROR_CODE.INTERNAL`.
4. **Результаты и отмена.** Перенести вызовы из списка ниже; существующие компоненты
   `UndoToastMessage` и `PwaOfferMessage` переиспользовать или адаптировать, не копировать.
   Проверить необходимость каждого подтверждения по принципу видимости результата.
5. **События и PWA.** Перевести событийные тосты на общий лимит, добавить отложенные
   события читалки и их актуализацию; связать программное скрытие PWA с текущими
   `onDismiss`, условиями установки, меню и жизненным циклом ожидающего воркера.
6. **Проверки и документация.** Общие истории, проверки очереди и интеграций,
   обновление решений и связанных планов. После завершения обновить статус этого плана.

### Проверка результата

- Тесты механизма с управляемым временем: общий лимит, вытеснение, защита отмен,
  приоритетная очередь, PWA без `onDismiss`, отсчёт только после показа и паузы.
- Повторы: общий сбой чтений объединяется, разные действия и отмены независимы,
  закрытое сообщение не появляется тут же из-за той же пачки, явная новая попытка не подавлена.
- Интеграции: ошибка возврата закрывает исходный тост и даёт ровно одну ошибку;
  исключения форм и офлайна, единственный выход при нескольких 401, очистка при смене аккаунта.
- Читалка: безопасность видна сразу, фоновые события ждут; после выхода каждый показан,
  обновлённые записи не дублируются, удалённые не воскресают.
- Истории группы «Тосты»: успех, предупреждение, ошибка, нейтральный и акцентный тон,
  предметное событие, отмена, установка, обновление, длинный текст, смешанный стек,
  переполнение и клавиатурный фокус. Проверить телефон и десктоп, светлую и тёмную темы,
  русский и английский. Сетевые сценарии мокируются через существующий MSW.
- Проверки реализации: ESLint, Stylelint для затронутых стилей, Prettier, `pnpm lint:i18n`,
  web typecheck и сборка; релевантные тесты механизма и истории. Изменение одного плана
  не требует запуска тестов приложения.

## Отвергнутые идеи

- Только косметическое обновление или миграция части тостов — нужна единая система целиком.
- Тост после каждого сохранения — видимое изменение само подтверждает действие.
- Общий лимит только у SSE — три места должны учитывать всех производителей.
- Потеря прежних отмен при следующем удалении — каждое действие сохраняет свою возможность возврата.
- Объединение исключительно по тексту — одинаковая ошибка может относиться к разным действиям.
- Постоянные ошибки и все тосты с действием — постоянными остаются предложения PWA;
  ошибки и отмены ограничены 10 с с паузами.
- Повтор возврата в том же тосте — пользователь выбрал закрытие и отдельное сообщение ошибки.
- Сводка после чтения или только точка на колокольчике — каждое актуальное отложенное событие
  показывается отдельно по правилам очереди.
- Все фоновые события во время чтения — остаются только безопасность и сообщения текущих действий.
- Универсальная отдельная ссылка «Открыть» для событий — карточка кликабельна целиком.
- Отказ от текущих исключений ошибок, дубли у полей или новая история тостов — вне выбранного решения.
