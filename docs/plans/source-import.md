# Импорт из источника

Статус: **Реализован** (разбор закладок — пока LibSocial и Desu) · 2026-10-26
Задача: `source-import` · ветка `feat/library-backup` · песочница `/playground/source-import`

## Зачем

Строка «Импорт из источника» в «Профиль → Данные» — заглушка ([12-todo](../12-todo.md#профиль--данные)):
сети и состояние входа в модалке `ImportFromSourceModal` настоящие, а чтение закладок
(`MOCK_PARSING_DURATION_MS`) и список тайтлов (`MOCK_IMPORT_TITLES`) — макет, «Импорт» отвечает
«Скоро будет доступно».

Кто приходит в tanuki с MangaLib или ReadManga, оставляет там библиотеку на сотни тайтлов с
папками и тем, где остановился. Переносить её руками по одному тайтлу никто не станет. Фича — для
любого вошедшего пользователя, у которого привязан аккаунт хотя бы одной сети со входом (гостей в
приложении нет).

Удача:

- закладки с сайта одним проходом ложатся в наши папки, свои папки сайта — нашими своими папками;
- «где остановился» с сайта становится отметкой прогресса — человек продолжает с той же главы;
- в непустую библиотеку ничего не перезаписывается без спроса: правила те же, что у
  восстановления из резервной копии, конфликты — вопросами;
- повторный импорт ничего не задваивает.

Остаётся как есть: утверждённый выбор источника (C1c, [Выбор источника для
импорта](../11-ui-decisions.md#выбор-источника-для-импорта)), точка входа в профиле, то, что войти
из модалки нельзя.

## Скоуп

- **Входит:**
  - метод парсера «закладки пользователя» для всех четырёх сетей со входом: Grouple (ReadManga,
    MintManga, SelfManga, SeiManga, Usagi), AllHentai (тот же движок), LibSocial (MangaLib,
    HentaiLib, SlashLib), Nude-Moon;
  - с сайта забираем: папку/статус, свои папки сайта, «где остановился» (номер последней главы);
  - серверное чтение (сводка) и запись — на логике `BackupRestoreService`/`backup-plan.ts`;
  - фоновая достройка отметок прогресса: таблица ожидания + крон;
  - уведомление «Импорт завершён» в ленте (категория «Аккаунт»);
  - модалка: источник → чтение → папки → вопросы (только при конфликтах) → готово; удаление
    моков `MOCK_IMPORT_TITLES`, `MOCK_PARSING_DURATION_MS`;
  - две точки входа: строка в «Профиль → Данные» и ссылка в описании `BookmarksEmpty` (закладок
    нет совсем). Кнопка в «Аккаунтах источников» отброшена по макетам (H0).
- **Не входит:**
  - двусторонняя синхронизация — ничего не пишем обратно на сайт;
  - авто-импорт по расписанию — только ручной запуск;
  - импорт с источников без входа (по ссылке на публичный профиль и т. п.);
  - отмена импорта после записи (как и у резервной копии);
  - статистика чтения: сайты не отдают журнал по главам, выдумывать даты не будем.

## Сценарии

### 1. Импорт из источника

1. Профиль → Данные → строка «Импорт из источника», кнопка «Импорт». Открывается модалка
   `ImportFromSourceModal` (тон `neutral`, иконка `CloudArrowDownIcon`).
2. **Шаг «Источник»** — как сейчас (C1c): рамки сетей с шапкой аккаунта, источники строками с
   радио, без входа — приглушены, кнопка «Войти»/«Войти заново» ведёт на вкладку аккаунтов. По
   умолчанию выбран первый источник со входом. Кнопка «Найти закладки».
3. **Шаг «Чтение»** — `POST /api/v1/source-import/preview` синхронно, до ~60 с. На шаге — `Loader`
   процесса (это экран процесса, не загрузка блока), «Читаем закладки на MangaLib», «Это может
   занять до минуты.», «Отмена» рвёт запрос (`AbortController`) и закрывает модалку.
   - Ошибка (сессия истекла, сайт лежит, таймаут) — тост глобального обработчика с текстом
     сервера, модалка возвращается на шаг «Источник», где шапка сети уже покажет «Нужен повторный
     вход» (инвалидация `useSourceAccounts`).
4. **Шаг «Папки»** — заголовок «Закладки на MangaLib», стрелка назад к источнику.
   - Выбор — целыми папками сайта, тайтлов на шаге нет (уточнено 2026-10-24: человек переносит
     библиотеку, а не перебирает сотни строк). У папки — название, куда она ляжет у нас и сколько
     тайтлов ляжет; сверху общий чекбокс «Выбрано: 4 папки, 87 тайтлов».
   - Порядок — как у папок пользователя в закладках, с учётом ручной перестановки. Новые и не
     поместившиеся папки — в конце, в порядке сайта.
   - Уже импортированное (этот же `titleKey` в той же папке) пропускается молча: у папки «9 новых
     из 24». Папки без новых тайтлов и расхождений папок или отметок скрыты.
   - Нового нет нигде — вместо списка и общего чекбокса заметка «Нового нет», «Импорт» выключен.
   - Кнопки «Отмена» и «Далее» (к вопросам) или «Импорт» (`type="submit"`), если в выбранных
     папках конфликтов нет.
5. **Шаг «Вопросы»** — только при конфликтах среди выбранных, как Q1a в копии:
   - «7 тайтлов уже в закладках, но в другой папке»: «Оставить мои» (по умолчанию) / «Взять из
     источника»;
   - «Где остановился: 5 отметок расходятся с вашими»: «Дальше прочитанное» (по умолчанию) / «Мой
     текущий» / «С источника».
   - Кнопки «Отмена» и «Импорт» (`type="submit"`). Назад — стрелка в заголовке.
6. **Шаг «Готово»** — тон `success`, `CheckCircleIcon`. Итог строками: добавлено закладок, новых
   источников у существующих, перенесено в другие папки, создано папок, папок не поместилось;
   «Где остановился: 112 отметок появятся в течение нескольких минут — пришлём уведомление».
   Кнопки «Закрыть» и «Открыть закладки».
7. Закрытие модалки на любом шаге до «Импорт» ничего не пишет.

### 2. Из аккаунтов источников

Отброшен по макетам 2026-10-24 (H0): шапка вошедшей сети остаётся без кнопки импорта, импорт —
из профиля и пустых закладок.

### 3. Из пустых закладок

1. Закладки, ни одной закладки нет ни в одной папке (`BookmarksEmpty`). Кнопка одна — «Открыть
   каталог»; описание продолжается ссылкой: «…на его странице или в читалке. Уже читаете на другом
   сайте? Импортируйте закладки» (E4).
2. Открывается модалка с шага «Источник», как из профиля. В пустой папке (`FolderEmpty`) и при
   пустом поиске (`SearchEmpty`) кнопки нет.
3. После записи список закладок инвалидируется — пустое состояние сменяется скелетоном и
   закладками.

### 4. Фоновая достройка отметок

1. «Импорт» записал закладки и положил в `source_import_progress` строку на каждый выбранный тайтл
   с номером главы с сайта.
2. Крон берёт порции, вызывает `getDetails` от имени аккаунта пользователя
   (`runWithSourceAccounts`), сопоставляет номер главы с главой ветки и пишет отметку по политике.
3. Когда у импорта не осталось ожидающих строк — уведомление `sourceImportFinished`: «Импорт из
   MangaLib завершён: отметки перенесены для 120 из 124 тайтлов». Клик — страница закладок
   (`ROUTE_PATHS.BOOKMARKS`).

### 5. Повторный импорт

То же, что сценарий 1. Уже импортированное пропускается, у папок — сколько нового; папки без
новых тайтлов и расхождений папок или отметок скрыты. Дублей не бывает: тайтл, попавший в группу, —
ещё один источник той же закладки.

## Логика и правила

### Папки

Сопоставление папки сайта с нашей — функция с исчерпывающим `switch` в парсере (статус сайта →
`BUILT_IN_BOOKMARK_FOLDER`) плюс правила копии для остального:

- стандартные статусы сайта («Читаю», «В планах», «Прочитано», «Брошено» и их аналоги) — во
  встроенные папки;
- «Любимое», «Любимые», «Любимый», «Любимая», «Избранное» / «Избранные» и
  Favorite(s) / Favourite(s) — во встроенное «Любимое», без учёта регистра и пробелов по краям;
  составные названия вроде «Любимые авторы» остаются своими папками;
- «Отложено» / On hold — во встроенное «Отложено», без учёта регистра и пробелов по краям;
- всё остальное (например, свои папки MangaLib) — своей папкой **по имени без учёта
  регистра**: совпала с нашей — туда, иконку/цвет/флаг не трогаем; нет — создаётся в конце
  (иконка `bookmark`, цвет `gray`, `trackUpdates: true`);
- сверх `CUSTOM_BOOKMARK_FOLDERS_LIMIT` — не создаются, их тайтлы ложатся во «В планах»; видно в
  списке (бейдж «В планах») и в итоге.

### Закладки

Та же таблица, что у восстановления (`backup-plan.ts`) — по `titleKey` и группе подтверждённых
совпадений; «Оставить мои» / «Взять из источника» = `RESTORE_FOLDER_POLICY.KEEP_MINE` /
`FROM_BACKUP`. Снимок (название, обложка, рейтинг, тип) — из ответа сайта.

### Отметки прогресса

- Политика — `RESTORE_PROGRESS_POLICY` (`furthest` / `keepMine` / `fromBackup`), выбирается при
  импорте и хранится в строке ожидания. Расхождения для вопроса считаются на сводке по
  `chapterNumber` (сайт его отдаёт, детали не нужны).
- Отметки нет — пишется при любой политике.
- Достройка: глава ищется по номеру в основной ветке (`branch` по умолчанию у `getDetails`); не
  нашлась — отметка пропускается и считается в «не перенесено».
- Пользователь удалил закладку до достройки — строка ожидания удаляется вместе с ней, отметка не
  пишется.

### Фоновая достройка — ограничения

- Крон (`@nestjs/schedule`, как `bookmark-updates.service`) раз в минуту, порция на источник с
  ограничением параллельности и паузой между запросами к одному сайту — чтобы не поймать
  рейт-лимит.
- До 3 попыток с паузой на тайтл; сессия истекла (`sourceReloginRequired`) — строки ждут
  повторного входа до суток, потом пропускаются.
- Переживает рестарт: всё состояние в БД.

### Права, параллельность, обратимость

- Только свои данные; запросы к сайту — от аккаунта пользователя, без сервисной учётки.
- Один пользователь — одна запись импорта за раз (advisory lock по `userId`, общий с
  восстановлением копии), второе отвечает 409. Новый импорт, пока предыдущий достраивается, —
  разрешён, строки ожидания копятся.
- Отмены нет; по умолчанию импорт только добавляет — тон модалки `neutral`, итог `success`, как у
  копии.

## Данные и API

### Парсеры (`packages/parsers`)

Новый необязательный метод `Parser`:

```ts
/** Закладки текущего аккаунта (`currentSourceAccount`); без аккаунта — ошибка входа. */
getBookmarks?(): Promise<RawBookmarkFolder[]>;
```

```ts
type RawBookmarkFolder = {
  /** Стандартный статус → встроенная папка; null — своя папка сайта. */
  builtIn: BuiltInBookmarkFolder | null;
  name: string;
  items: RawBookmark[];
};
type RawBookmark = {
  titleId: string; // как в getList — по нему строится titleKey
  name: string;
  coverUrl: string | null;
  contentRating: ContentRating | null;
  type: TitleType | null;
  /** Номер последней прочитанной главы, если сайт его отдаёт. */
  lastChapterNumber: number | null;
};
```

Реализации: `grouple/engine.ts` (Grouple и AllHentai), `libsocial/engine.ts`, `nudemoon`. Первый
шаг каждой — разведка живого сайта: где лежат закладки, отдаёт ли сайт папки и последнюю главу,
пагинация. Чего сайт не отдаёт, то `null`/встроенная «В планах». Фикстуры и тесты — в
`packages/parsers/test`.

### Контракты (`packages/contracts/src/source-import.ts`)

- `SourceImportPreviewRequest` — `{ sourceId }`;
- `SourceImportPreview` — папки сайта без списка тайтлов: `folderId`, название, `targetFolder`
  (наша папка или «создастся»), счётчики `total` / `fresh` (не импортированных раньше) /
  `otherFolder` / `progressDiff`; по ним клиент считает итог выбора и нужен ли шаг «Вопросы»;
- `SourceImportRequest` — `sourceId`, выбранные `folderIds`, `folderPolicy`, `progressPolicy`;
- `SourceImportResult` — счётчики итога и `pendingProgress`.

Сайт читается дважды (сводка и запись) — сервер не хранит сводку между запросами; запись
перечитывает закладки, чтобы не доверять присланным снимкам.

### Эндпоинты (`apps/api/src/source-import`, `SourceImportModule`)

| Метод и путь                         | Тело / ответ                                         |
| ------------------------------------ | ---------------------------------------------------- |
| `POST /api/v1/source-import/preview` | `SourceImportPreviewRequest` → `SourceImportPreview` |
| `POST /api/v1/source-import`         | `SourceImportRequest` → `SourceImportResult`; 409    |

Источник без входа, выключенный или скрытый 18+ — 403 с теми же кодами, что у каталога
(`sourceAccountRequired`, `sourceReloginRequired`).

Запись папок и закладок — выносим общую часть `BackupRestoreService` (`writeFolders`,
`writeBookmarks`, `planFolders`, `isFurther`) в переиспользуемый сервис библиотеки, импорт и
восстановление зовут её.

### Таблица (`apps/api/src/database/schema.ts`)

`source_import_progress`: `id`, `userId`, `importId` (группирует строки одного импорта для
уведомления), `sourceId`, `titleId`, `chapterNumber`, `progressPolicy`, `status`, `attempts`,
`nextAttemptAt`, `createdAt`. Каскадное удаление с пользователем и с закладкой.

### Web

- `ImportFromSourceModal` переезжает из `pages/Profile/components/ProfileData` в
  `features/source-import/` — у неё два потребителя (профиль «Данные», `pages/Bookmarks`). Вместе с ней — то, что она берёт из `ProfileSourceAccounts`
  (`useSourceAccounts`, `groupSourcesByAccount`, `getSourcesWithoutLogin`,
  `SourceAccountStatusIcon`, статусные `lib`): в `entities/source` или туда же в `features/`.
- Мутации `useSourceImportPreview` и `useSourceImport` в `hooks/`;
  после записи — инвалидация закладок, папок, прогресса.
- Уведомление `sourceImportFinished`: текст и цель клика в существующих `switch` ленты.
- Тексты: `importDoesNotOverwriteProgress` («Импорт не перезаписывает прогресс…») больше не
  правда — удаляется; новые ключи — по правилам локализации.

## Крайние случаи

| Случай                                          | Что видит пользователь                                                         |
| ----------------------------------------------- | ------------------------------------------------------------------------------ |
| Импорт из пустых закладок, но входа нет нигде   | модалка с шагом «Источник»: кнопки «Войти» в шапках сетей                      |
| Ни одного источника со входом                   | шаг «Источник» без радио, «Найти закладки» `disabled`, кнопки «Войти» в шапках |
| Источник выключен или скрыт настройкой 18+      | его нет в модалке; сеть без видимых источников не показывается                 |
| Сессия истекла / сайт лежит / таймаут на чтении | тост с текстом сервера, возврат к «Источник» (шапка — «Нужен повторный вход»)  |
| На сайте нет закладок                           | шаг «Папки» — `EmptyState` «На MangaLib закладок нет», кнопка назад            |
| Всё уже импортировано                           | заметка «Нового нет», список и общий чекбокс скрыты, «Импорт» `disabled`       |
| Ничего не выбрано                               | «Импорт» `disabled`, общий чекбокс снят                                        |
| Сотни тайтлов                                   | на шаге только папки — их единицы, тайтлы не перечисляются                     |
| Своих папок сайта больше лимита                 | у папки «→ в „В планах“», в итоге «N папок не поместились»                     |
| Сайт не отдаёт последнюю главу                  | отметка не создаётся, в итоге не считается                                     |
| Глава не нашлась при достройке                  | отметки нет; в уведомлении «120 из 124»                                        |
| Закладку удалили до достройки                   | отметка не пишется, тайтл не считается                                         |
| Второй импорт/восстановление параллельно        | тост об ошибке (409), модалка остаётся на шаге                                 |
| Офлайн                                          | «Импорт» в профиле `disabled`, как «Скачать копию»                             |
| Длинные названия папок                          | переносятся, счётчик не сжимается                                              |

## Дизайн

**Где живёт.** «Профиль → Данные», блок «Импорт и экспорт», строка «Импорт из источника» — без
изменений (иконка `CloudArrowDownIcon`, «Закладки из вашего аккаунта на источнике», кнопка
«Импорт»). Вторая точка входа — ссылка «Импортируйте закладки» в конце описания `BookmarksEmpty`
(E4); в «Аккаунтах источников» кнопки нет (H0).

**Выбрано по макетам:** **F1 + S + Q + G3 + H0 + E4** — шаг «Папки» рамкой `GroupedList` со
словами, куда ляжет каждая папка; «Вопросы» как Q1a копии; «Готово» со строкой «Где остановился —
переносим» и `Loader`. Подробно — [11-ui-decisions: Импорт из
источника](../11-ui-decisions.md#импорт-из-источника).

**Модалка** — `ToneModal`, до пяти шагов в одной модалке, как `RestoreBackupModal`: источник →
чтение → папки → вопросы → готово. Стрелка назад — на «Папки» и «Вопросы». Тон `neutral`
(`CloudArrowDownIcon`), на «Готово» — `success` (`CheckCircleIcon`). Главное — 14, пояснения —
`<Text c="dimmed" fz={13}>`; счётчики и номера глав — `ff="monospace"`. Шаг «Вопросы» и «Готово»
визуально повторяют копию (Q1a, D1) — переиспользуем `RestoreQuestions` и строки итога, вынося их в
общий компонент (второй потребитель).

Мобилка и десктоп — одна раскладка; на телефоне модалка в ширину экрана, список папок

## Чем реализация отличается от плана

- **Ветка** — `feat/library-backup`, а не своя: импорт опирается на код копии, ещё не влитый в
  master (решение пользователя).
- **Движки** (этапы 1–2): готов каркас — `RawBookmarkFolder`/`RawBookmark` (у папки есть `id` —
  по нему выбирают папки), `Parser.getBookmarks?`, `RawSourceInfo.isBookmarksImportSupported`
  (реестр выводит его из наличия метода) и `Source.isBookmarksImportSupported`. Разбор сайтов ждёт
  образцов ответов с вошедшим аккаунтом; до тех пор источник в модалке приглушён с подписью
  «Импорт отсюда пока не поддерживается».
- **Строки ожидания** хранят и `titleKey` — для каскадного удаления вместе с закладкой (FK на
  `bookmarks (user_id, title_key)`); в ожидание кладётся только то, что политика разрешит
  записать (у `furthest` — если глава сайта дальше), а на записи политика проверяется ещё раз.
- **Общая запись** вынесена в `library/library-merge.ts` (`planFolders`, `listUntrackedMovedKeys`)
  и `LibraryMergeService` (замок, папки, закладки); `isFurther` остался у копии — импорт
  сравнивает только номер главы (`winsSiteProgress`).
- **«Где остановился» — том и номер**, а не только номер (найдено на живом импорте 2026-10-26): у
  LibSocial нумерация глав начинается заново в каждом томе, у «Ветролома» 129 номеров из 184
  повторяются. `RawBookmark.lastChapterVolume`, колонка `chapter_volume` у строки ожидания;
  «дальше» сравнивает сначала том, если он известен у обеих сторон. Без тома неоднозначный номер
  не угадывается — отметка пропускается.
- **Глава ищется во всех ветках**, начиная с основной: ветка у LibSocial — команда переводчиков,
  у долгих тайтлов команды сменяются, и ранних томов в основной ветке нет.
- **Текст 409** стал общим: «Импорт или восстановление библиотеки уже идёт — дождитесь окончания».

## Отвергнутые идеи

- **Фоновая задача на всё чтение** — модалка ждёт синхронно до минуты, проще и хватает.
- **`getDetails` всех тайтлов уже на чтении** — сотня тайтлов не укладывается в минуту.
- **Отметка только по номеру, без `chapterId`** — меняет схему и чтение прогресса везде.
- **Достройка в процессе после ответа** — рестарт теряет недостроенное.
- **Сводка счётчиками без потайтлового выбора** — человек хочет снять конкретные тайтлы.
- **Выбор нашей папки для каждой папки сайта на шаге «Вопросы»** — длинно; хватает правил копии.
- **Всё несопоставленное — во «В планах»** — тогда свои папки сайта теряются.
- **Экран ошибки внутри модалки** — ошибки показывает глобальный обработчик.
- **Показывать выключенные/18+ источники приглушёнными** — их нет нигде в приложении, и здесь нет.
- **Пропускать шаг «Источник» при входе из аккаунтов** — в LibSocial несколько сайтов, выбор
  нужен.
- **Кнопка импорта в пустой папке и пустом поиске** — там библиотека уже есть, импорт не главное
  действие.
- **Импорт журнала глав в статистику** — сайты его не отдают, даты пришлось бы выдумывать.
