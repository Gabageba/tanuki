# Уведомления

Статус: **Реализован** · 2026-10-09
Задача: `notifications` · ветка `feat/notifications` · песочница `/playground/notifications`

## Зачем

Колокольчик в шапке и футере и маршрут `/notifications` существуют, но это каркас: `pages/Notifications`
выводит одно слово, у колокольчика нет ни действия, ни счётчика. При этом события, о которых стоит
сообщать, уже случаются, а человек узнаёт о них только случайно:

- крон закладок (`BookmarkUpdatesService`) находит новые главы, а видно их только по точке на
  закладках, если открыть приложение;
- источник из закладок может лечь (`SOURCE_STATUS.DOWN`), и человек видит это, лишь упёршись в ошибку;
- смена почты и запрос удаления аккаунта уходят письмом, а внутри приложения следа нет;
- админы и модераторы не узнают о лёгшем источнике, пока не зайдут в `SourcesHealth`.

Для кого: любой вошедший пользователь (гостей в приложении нет); отдельные категории — для `admin` и
`moderator`.

Удача:

- человек узнаёт о новой главе, не открывая приложение (Web Push);
- о важном — входе с другого устройства, лёгшем источнике, событии для админа — он узнаёт
  **моментально**, и когда приложение закрыто (push), и когда открыто (поток SSE и тост поверх экрана);
- открыв приложение, сразу видит, что произошло, и одним кликом попадает к нужному тайтлу или экрану;
- лента не расходится с закладками и не засоряется: один тайтл — одно уведомление.

Остаётся как есть: точка «новые главы» на закладках, в шапке и футере (план закладок) работает как
раньше. Лента — журнал событий, а не её замена.

## Скоуп

- **Входит:**
  - модель уведомлений на сервере, страница `/notifications` с фильтром по категории;
  - четыре категории: новые главы, аккаунт, источники, администрирование;
  - Web Push: подписка устройства, отправка, тумблер на устройстве и по категориям;
  - поток SSE для открытого приложения: мгновенный бейдж, обновление ленты и тост о важных событиях;
  - минимальный service worker и веб-манифест (только `push` и `notificationclick`, без офлайн-кэша);
  - вкладка «Уведомления» в настройках;
  - бейдж с числом непрочитанных на колокольчике (шапка и футер);
  - предложение включить push после первого добавления в отслеживаемую папку;
  - таблица известных устройств для события «вход с нового устройства».
- **Потом:**
  - Telegram-бот (пункт роадмапа «После релиза»);
  - офлайн-кэш ленты и полный PWA-каркас Фазы 4 (precache, офлайн-читалка) — SW из этой задачи станет
    его основой;
  - тихие часы, сводка вместо россыпи пушей (см. «Открытые вопросы»).
- **Не входит:**
  - письма-дайджесты о новых главах (почта остаётся только для системных писем);
  - уведомления вне перечисленных типов (отзывы, комментарии — их в приложении нет);
  - вебсокеты (канал односторонний, хватает SSE);
  - всплывающий поповер с последними уведомлениями у колокольчика.

## Сценарии

### 1. Узнать о новой главе

1. Пользователь добавил тайтл в папку со «Следить за обновлениями» (план закладок).
2. Крон проходит по тайтлам, находит новые главы и считает `newChaptersCount` группы закладки.
3. Если число больше нуля, создаётся (или обновляется) уведомление «Берсерк: 3 новые главы».
4. Если на устройствах есть подписки и категория «Новые главы» включена для push, на них уходит push.
   Если приложение открыто и видимо, система push не показывает: событие приходит по SSE, бейдж растёт
   сразу, лента обновляется (тоста для новых глав нет).
5. Клик по push открывает приложение на странице тайтла на источнике карточки закладки; уведомление
   при этом удаляется.

### 2. Открыть ленту

1. Пользователь жмёт колокольчик (шапка на десктопе, футер на мобилке) → `/notifications`.
2. Видит непрочитанные уведомления, новые сверху, по 20 на страницу (`ListPagination`).
3. Может сузить список фильтром по категории (`CompactMultiSelect`; пустой выбор — без ограничения).
4. Клик по уведомлению ведёт к цели (таблица в «Логике») и считает его прочитанным: оно исчезает из ленты.
5. Крестик «×» на строке убирает уведомление без перехода.
6. Кнопка «Отметить все уведомления прочитанными» убирает всё (с учётом выбранного фильтра).
7. Само открытие ленты ничего не прочитывает.

### 3. Мгновенный сигнал в открытом приложении

1. Приложение открыто, SSE-соединение установлено.
2. Сервер создал уведомление пользователю (например, `newDeviceLogin` или `sourceDown`).
3. По потоку приходит событие; клиент обновляет счётчик и сбрасывает кэш ленты.
4. Для категорий «Аккаунт», «Источники» и «Администрирование» поверх экрана появляется тост с
   текстом и ссылкой на цель. Для «Новых глав» тоста нет, меняется только бейдж.
5. Если вкладка не видима, тост не копится: о событии уже сообщил push.

### 4. Включить push

Точки входа:

- **После первого добавления в закладки.** Тайтл добавлен в папку с «Следить за обновлениями»; push на
  этом устройстве не включён; на инстансе заданы VAPID-ключи; браузер умеет push; «Не сейчас» на этом
  устройстве ещё не нажимали. Показывается предложение с кнопкой «Включить push-уведомления» и «Не сейчас».
  «Не сейчас» запоминается в `localStorage` (выбор per-device, на других устройствах предложение
  появится само).
- **Вкладка «Уведомления» в настройках** — тумблер «Push на этом устройстве».

Шаги: кнопка/тумблер → системный запрос разрешения браузера (только по клику) → подписка в
`pushManager` → `POST /notifications/push/subscriptions` → тумблер включён.

Выключение: тумблер → отписка в браузере + `DELETE` подписки на сервере.

### 5. Настроить категории

Вкладка «Уведомления» в настройках: тумблеры push по категориям — «Новые главы», «Аккаунт»,
«Источники» и (только `admin`/`moderator`) «Администрирование». Настройка аккаунтная, а не
устройственная: действует на все устройства человека.

### 6. Системные события

- Сменили почту / запросили удаление аккаунта / вошли с нового устройства — запись попадает в ленту
  и уходит push.
- Источник из закладок лёг или ожил — одна запись на источник, см. «Логику».
- Админ или модератор: источник перешёл в `down` или вернулся; админ: пользователь зарегистрировался
  по инвайту, инвайт истёк.

## Логика и правила

### Enum'ы (`packages/contracts/src/notification.ts`)

```ts
export const NOTIFICATION_CATEGORY = {
  CHAPTERS: 'chapters',
  ACCOUNT: 'account',
  SOURCES: 'sources',
  ADMINISTRATION: 'administration',
} as const;

export const NOTIFICATION_TYPE = {
  NEW_CHAPTERS: 'newChapters',
  EMAIL_CHANGED: 'emailChanged',
  DELETION_REQUESTED: 'deletionRequested',
  NEW_DEVICE_LOGIN: 'newDeviceLogin',
  SOURCE_DOWN: 'sourceDown',
  SOURCE_RECOVERED: 'sourceRecovered',
  PARSER_DOWN: 'parserDown',
  PARSER_RECOVERED: 'parserRecovered',
  INVITE_USED: 'inviteUsed',
  INVITE_EXPIRED: 'inviteExpired',
  SOURCE_IMPORT_FINISHED: 'sourceImportFinished',
} as const;
```

Тип → категория и тип → цель клика — функции с исчерпывающим `switch` (`getNotificationCategory`,
`getNotificationTarget`), не таблицы-словари.

### Кому и когда создаётся

| Тип                              | Получатель                                                | Условие                                                                                                             |
| -------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `newChapters`                    | владелец закладки                                         | папка с `trackUpdates`, у группы `newChaptersCount > 0`                                                             |
| `emailChanged`                   | сам пользователь                                          | почта сменена (вместе с существующим письмом)                                                                       |
| `deletionRequested`              | сам пользователь                                          | запланировано удаление аккаунта                                                                                     |
| `newDeviceLogin`                 | сам пользователь                                          | вход, отпечатка которого нет в `known_devices` (первый вход аккаунта не считается)                                  |
| `sourceDown` / `sourceRecovered` | пользователи с закладкой на этом источнике, в любой папке | `SourceStatusService`: переход в `down` / возврат в `ok`; `degraded` не шумит; отключённые источники пропускаются   |
| `parserDown` / `parserRecovered` | все `admin` и `moderator`                                 | любой источник перешёл в `down` (причина из `SOURCE_STATUS_REASON`) / вернулся                                      |
| `inviteUsed`                     | `admin`                                                   | пользователь зарегистрировался по инвайту                                                                           |
| `inviteExpired`                  | `admin`                                                   | инвайт истёк неиспользованным                                                                                       |
| `sourceImportFinished`           | сам пользователь                                          | у импорта из источника не осталось ждущих отметок «где остановился» (категория «Аккаунт», [план](source-import.md)) |

### Группировка и обновление

- Уведомление уникально по `(userId, groupKey)`; создание — upsert.
- `newChapters`: `groupKey = chapters:<ключ группы закладки>`. Крон **выставляет** `count` равным
  текущему `newChaptersCount` (не прибавляет), поэтому повторный проход идемпотентен. Пока
  уведомление не прочитано, новые главы лишь меняют `count` и `updatedAt`.
- Источники: `groupKey = source:<sourceId>` (у админов `parser:<sourceId>`). Переход в `down` создаёт
  или переписывает запись типом `sourceDown`; возврат переписывает её на `sourceRecovered` и снова
  делает непрочитанной (если запись уже прочитана и удалена, создаётся новая).
- **Push уходит**, когда запись создана или переписана сменой типа; рост `count` push не повторяет.
- Одноразовые события (аккаунт, инвайты) — запись на событие, `groupKey` уникален (`event:<uuid>`).

### Прочитанность

- «Прочитано» = запись **удаляется** (hard delete). Столбца `readAt` нет: лента показывает только
  непрочитанное, прочитанные не хранятся.
- Три способа: клик по уведомлению (удаляет и ведёт к цели), «×» (удаляет без перехода), «Отметить все
  уведомления прочитанными» (`DELETE /notifications`, опционально с `category`).
- Визит в группу закладки (открытие страницы тайтла любого источника группы или сохранение прогресса
  — тот же «визит» из плана закладок) удаляет `newChapters`-запись этой группы.
- Удаление закладки или отключение «Следить за обновлениями» у папки удаляет `newChapters`-записи этих
  закладок.

### Куда ведёт клик

| Тип                              | Цель                                                                     |
| -------------------------------- | ------------------------------------------------------------------------ |
| `newChapters`                    | страница тайтла на источнике карточки закладки (источник свежей отметки) |
| `emailChanged`, `newDeviceLogin` | профиль / безопасность (точный экран — по факту реализации)              |
| `deletionRequested`              | `AccountDeletionScheduled`                                               |
| `sourceDown`, `sourceRecovered`  | список источников в настройках (`Sources`)                               |
| `parserDown`, `parserRecovered`  | `SourcesHealth`                                                          |
| `inviteUsed`, `inviteExpired`    | `Management` → инвайты                                                   |
| `sourceImportFinished`           | закладки (`ROUTE_PATHS.BOOKMARKS`)                                       |

### Push

- Push — опция инстанса: без VAPID-ключей в конфиге API блок push нигде не показывается, лента и
  бейдж работают. То же — если браузер не умеет push (в т. ч. iOS вне установленного PWA).
- Разрешение браузера запрашивается только по клику пользователя.
- Категория «Аккаунт» не отключается в ленте. Для push у неё обычный тумблер, по умолчанию включён.
- Если приложение открыто и видимо, SW push не показывает: то же событие приходит по SSE и
  показывается тостом/бейджем. Это упирается в ограничение WebKit — см. «Открытые вопросы».
- Подписка с ответом 404/410 от push-сервиса удаляется автоматически.
- Текст push формируется на сервере на языке пользователя (`user_settings.language`); текст ленты —
  на клиенте по `type` и `payload` через i18n, а не хранится готовой строкой.

### Поток SSE

- Эндпоинт `GET /notifications/stream` (сессионная cookie, `EventSource` того же origin). Сервер шлёт
  событие при каждом создании или переписывании уведомления пользователя, а также при удалении
  (прочитано в другой вкладке): `{ type: 'created' | 'updated' | 'removed', notification? }`.
- Раз в 25 с сервер шлёт комментарий-heartbeat, чтобы соединение не рвали прокси; ответ идёт с
  `X-Accel-Buffering: no` и без компрессии.
- Клиент держит **одно** соединение на вкладку и закрывает его при выходе из аккаунта. Не более 5
  одновременных потоков на пользователя, лишние старые закрываются.
- Пока соединение не установлено (старт, обрыв, браузер без `EventSource`), включается опрос
  `GET /notifications/unread-count` раз в минуту. При (пере)подключении клиент один раз заново
  запрашивает счётчик и ленту, поэтому пропущенные события не теряются.
- Рассылка идёт через внутренний хаб `NotificationsModule` (RxJS `Subject` по `userId`); при нескольких
  репликах API его заменяет pub/sub в Valkey — см. «Открытые вопросы».
- Тост показывается для событий `created`/`updated` категорий `account`, `sources`, `administration`;
  `removed` и `chapters` обновляют только бейдж и ленту.

### Хранение и очистка

- Непрочитанные живут 30 дней от `updatedAt`; суточный крон (как `AuthCleanupService`) удаляет старше.
- Не более 200 записей на пользователя: при переполнении удаляются самые старые.

## Данные и API

### Контракты (`packages/contracts/src/notification.ts`, `user-settings.ts`)

- Enum'ы выше, схемы `NotificationItem` (`id, type, category, payload, count, createdAt, updatedAt`),
  `NotificationsPage` (`items, total`), `UnreadCount`, `PushConfig` (`enabled, publicKey`),
  `PushSubscriptionInput`.
- `payload` — discriminated union по `type`: для `newChapters` — `titleKey/titleId/sourceId`, снимок
  `name`, `coverUrl`; для источников — `sourceId`, `reason`; для `newDeviceLogin` — подпись устройства
  («Chrome · macOS»); для инвайтов — `inviteId`, ник нового пользователя.
- `UserSettings` получает `pushDisabledCategories: NotificationCategory[]` (`null` на сервере — всё
  включено, как `collapsedSearchSources`).

### API (`NotificationsModule`)

```
GET    /notifications?category=&page=&pageSize=   → NotificationsPage (непрочитанные, новые сверху)
GET    /notifications/unread-count                → { count }
GET    /notifications/stream                      → text/event-stream
DELETE /notifications/:id                         → 204 (прочитано / убрать)
DELETE /notifications?category=                   → 204 (отметить всё прочитанным)
GET    /notifications/push/config                 → { enabled, publicKey }
POST   /notifications/push/subscriptions          → 204 (endpoint, keys)
DELETE /notifications/push/subscriptions          → 204 (по endpoint)
```

Администрирование видят только `admin`/`moderator`; фильтр по чужой категории даёт пустой список, а не 403. Лимитер как у остальных эндпоинтов; `stream` ограничен по числу соединений, опрос счётчика работает
только в простое потока.

### Таблицы (`apps/api/src/database/schema.ts`)

- `notifications` — `id`, `userId` (cascade), `type`, `groupKey`, `payload` jsonb, `count`,
  `createdAt`, `updatedAt`. Уникальный `(userId, groupKey)`, индекс `(userId, updatedAt)`.
- `push_subscriptions` — `id`, `userId` (cascade), `endpoint` unique, `p256dh`, `auth`, `userAgent`,
  `createdAt`.
- `known_devices` — `id`, `userId` (cascade), `fingerprint` (хэш пары «браузер + ОС» из
  `sessions.userAgent`), `label`, `firstSeenAt`, `lastSeenAt`; уникальный `(userId, fingerprint)`.
  Миграция засевает её из существующих `sessions`, иначе все получат ложное «новое устройство».
- `user_settings.push_disabled_categories` — `text[]`.

### Источники событий в коде

- `BookmarkUpdatesService` — после прохода и дотяжки, `newChapters`.
- Обработчики визита и закладок в `LibraryModule` — удаление `newChapters`.
- `SourceStatusService` — переходы `down` / `ok`.
- `AuthModule` / `UsersModule` — смена почты, запрос удаления, вход (отпечаток устройства).
- `InvitesService` — регистрация по инвайту; истечение — отдельный суточный/часовой крон, так как статус
  инвайта вычисляется на чтении и события «истёк» в коде нет.
- Отправка push — `web-push` (новая зависимость), ключи `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`,
  `VAPID_SUBJECT` в конфиге API.

### Web

- `entities/notification` — запросы и хуки (`useNotificationsQuery`, `useUnreadNotificationsCount`
  с `refetchInterval: 60_000` только пока SSE не подключён), `useNotificationsStream` (одно
  соединение на вкладку, обновление кэша React Query, тост), `getNotificationTarget`.
- `pages/Notifications` — лента; `pages/Settings/components/SettingsNotifications` — вкладка;
  `features/notification/PushPrompt` — предложение включить push.
- `vite-plugin-pwa` в режиме `injectManifest`, `src/sw/sw.ts` с обработчиками `push` и
  `notificationclick`, веб-манифест (имя, иконки, `display: standalone`) — как заложено в
  `docs/06-pwa-offline.md`, но без precache и офлайн-логики.
- Тексты — `ru.json` / `en.json`; плюрализация «N новых глав».

## Крайние случаи

| Случай                                              | Что видит пользователь                                                                        |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Загрузка ленты                                      | `BlockLoader`: лента может оказаться пустой, скелетон не подходит                             |
| Лента пуста                                         | `EmptyState` «Новых уведомлений нет»                                                          |
| Ошибка запроса ленты                                | `QueryError` в `PageLayout.Content` (это основной запрос страницы)                            |
| Ошибка счётчика                                     | бейджа нет, тост от глобального обработчика                                                   |
| Загрузка вкладки настроек                           | скелетон формы                                                                                |
| Нет сети                                            | лента не открывается (офлайн-кэша нет); push приходит и офлайн, клик открывает приложение     |
| На инстансе нет VAPID-ключей                        | блока push нет ни в настройках, ни в предложении; лента работает                              |
| Браузер без push / iOS вне установленного PWA       | блок push скрыт или объясняет «Установите приложение на главный экран»                        |
| Разрешение запрещено в браузере                     | тумблер выключен, подсказка «Разрешите уведомления в настройках браузера»                     |
| Подписка протухла (404/410)                         | запись удаляется, тумблер на устройстве становится выключенным                                |
| Тайтл удалён из закладок после уведомления          | запись `newChapters` удаляется вместе с закладкой                                             |
| Источник карточки недоступен при клике              | обычное состояние страницы тайтла                                                             |
| Больше 99 непрочитанных                             | бейдж «99+»                                                                                   |
| 200+ уведомлений                                    | самые старые удалены сервером                                                                 |
| Название тайтла длинное                             | обрезается в одну-две строки                                                                  |
| Поток SSE оборвался                                 | клиент переподключается, до этого счётчик опрашивается раз в минуту; после — ленту дотягивает |
| Браузер без `EventSource` / прокси буферизует поток | опрос раз в минуту, всё остальное работает                                                    |
| Несколько вкладок                                   | в каждой своё соединение (не более 5 на пользователя), тост показывается в видимой вкладке    |
| Выход из аккаунта                                   | поток закрывается, кэш уведомлений сбрасывается                                               |
| Событие пришло, пока вкладка скрыта                 | push показал системное уведомление; тост не копится                                           |
| Пользователь без закладок на лёгшем источнике       | `sourceDown` не создаётся                                                                     |
| Модератор получает `parserDown`, но не `inviteUsed` | категория «Администрирование» у него без инвайтов                                             |

## Дизайн

**Где живёт.**

- Колокольчик остаётся в `Header` и `Footer` и ведёт на `/notifications` — один вид на мобилке и десктопе.
  На нём бейдж с числом непрочитанных (отдельно от точки закладок, которая не исчезает).
- Страница `/notifications` внутри `PageLayout`: заголовок, фильтр по категории (`CompactMultiSelect`),
  кнопка «Отметить все уведомления прочитанными», список, `ListPagination`, `EmptyState`.
- Строка уведомления: слева иконка категории или обложка тайтла, заголовок (одно предложение), второй
  строкой уточнение и время (`formatRelative`), справа «×» (`ActionIcon`). Непрочитанность отдельного
  маркера не требует: в ленте только непрочитанное.
- Вкладка «Уведомления» в настройках: блок устройства (тумблер push) и блок категорий (тумблеры);
  вкладка строится из массива `TABS`, как остальные.
- Тост (Mantine `notifications.show`) для важных событий: иконка категории, одно предложение, ссылка
  на цель; закрывается сам.
- Предложение включить push — мягкий нативный для приложения элемент после добавления в закладки
  (не системный диалог), вид — вопрос к макетам.
- Обе темы: цвета только Mantine-переменные; иконки из `@phosphor-icons/react`; числа в бейдже —
  моноширинный шрифт, фраза «3 новые главы» — Golos Text.
- Модалок в этой фиче нет: «Отметить всё» и «×» обратимы по смыслу (читаемое всё равно исчезает),
  подтверждения не требуют.

**Терминология.**

| Понятие                       | Как называем в UI                                     |
| ----------------------------- | ----------------------------------------------------- |
| Фича                          | Уведомления                                           |
| Прочитанное                   | прочитанное (исчезает из ленты)                       |
| Системное оповещение браузера | Push-уведомления                                      |
| Режим отслеживания папки      | Следить за обновлениями (как в закладках)             |
| Категории                     | Новые главы · Аккаунт · Источники · Администрирование |

**Референсы.** Лента «Входящие» (Gmail: прочитанное уходит), уведомления GitHub (отметить всё,
фильтры). **Антиреференс:** «все уведомления вечно, прочитанные серым» — шум, который здесь не нужен.

**Выбранный вариант** (подробно — [11-ui-decisions.md#уведомления](../11-ui-decisions.md#уведомления)):
R2 + L1 + N1 + B2 + F1 + бесконечная прокрутка + E3 без ссылки + T1 + D1 + Q1 (до 3) + K4/M3 + X3 +
стандартный `GroupedList` в настройках. Иконки квадратные, «убрать» — корзина.

## Вопросы к макетам

1. **Строка ленты.** Обложка тайтла против иконки категории; как показать счётчик глав («+3» в
   моноширинном шрифте или словами); различимость типов (цвет иконки по тону: жёлтый — источник лёг,
   бирюзовый — ожил, красный — безопасность).
2. **Фильтр категорий.** `CompactMultiSelect` в шапке страницы или чипы-вкладки; поведение на мобилке.
3. **Бейдж колокольчика.** Число или точка; «99+»; как уживается с точкой «новые главы» на закладках.
4. **Предложение включить push.** Баннер над контентом, тост с действием или встроенная плашка у
   `Select` папки; как выглядит «Не сейчас»; состояние «выбрано, но браузер запретил».
5. **Вкладка настроек.** Все состояния блока устройства: нет поддержки / запрещено в браузере /
   выключено / включено; скрытие категории «Администрирование» для обычных пользователей.
6. **Пагинация против бесконечного скролла.** Склоняюсь к `ListPagination` (общее правило), но
   проверить на мобилке.
7. **Тост о событии.** Тон по категории, длительность (безопасность держим дольше), кликабельность
   всего тоста против отдельной ссылки, поведение, если событий несколько подряд.
8. **Пустая лента.** Тон текста и нужны ли в пустом состоянии ссылки («Перейти в закладки»).

**Закрыто макетами:**

1. Строка ленты — R2, L1, N1; значки — X3.
2. Фильтр — F1 (`CompactMultiSelect`).
3. Бейдж — B2, точка без обводки.
4. Предложение push — K4, вид M3.
5. Вкладка настроек — один `GroupedList`.
6. Пагинация — бесконечная прокрутка, а не `ListPagination`.
7. Тост — T1 + D1 + Q1 (не больше трёх).
8. Пустая лента — E3 без ссылки «Перейти в закладки».

1. ✅ **Контракты** — `notification.ts` (enum'ы, схемы), `pushDisabledCategories` в `user-settings.ts`.
2. ✅ **API** (+ тесты) — таблицы и миграция (с засевом `known_devices`), `NotificationsModule`
   (сервис, контроллер, хаб и SSE-эндпоинт, отправка push, суточная очистка), подключение источников событий
   (закладки, источники, аккаунт, инвайты), конфиг VAPID, тесты сервисов.
3. ✅ **Web без макетов** — `vite-plugin-pwa` + `sw.ts` + манифест, `entities/notification`,
   подписка на push (хук), `useNotificationsStream` (SSE + запасной опрос), `getNotificationTarget`,
   локали, маршрут.
4. ✅ **Web по макетам** — страница ленты, бейдж, вкладка настроек, предложение push.
5. ✅ **Docs** — см. ниже.

Пункты 1–3 можно делать до макетов.

**Как этап 2 отличается от плана** (реализовано 2026-10-09):

- `known_devices` не засевается SQL-миграцией: отпечаток считается из User-Agent библиотекой
  `bowser`, в SQL его не повторить. Вместо этого `DeviceLoginService` при первом входе после
  выкладки (таблица пуста, сессии есть) засевает устройства из прежних сессий сам и вызывается до
  создания новой сессии — иначе новое устройство сравнивалось бы с самим собой.
- Истечение инвайтов ловит почасовой крон по окну «истёк за прошедший час», без отдельной
  отметки «уведомлён»; окна идут встык, но если API не работал в этот час, уведомление пропадёт.
- Новые главы создаются только для групп, чьи главы найдены в этом проходе крона (иначе убранная
  «×» запись возвращалась бы при каждом проходе). Записи групп без новых глав чистятся при
  каждом проходе; визит, удаление закладки и выключение слежения в папке убирают запись сразу.
- В потоке SSE пульс — событие `ping` с пустыми данными, а не комментарий: `@Sse()` Nest
  комментариев не умеет. `EventSource` на неподписанное событие не реагирует.
- `removed` без `id` — удалена пачка («убрать все», переполнение): клиент перезапрашивает ленту.

**Как этапы 3–4 отличаются от плана** (реализовано 2026-10-09):

- Фильтр категорий мультивыборный, а `GET`/`DELETE /notifications` принимали одну `category`:
  параметр стал списком через запятую (`?category=chapters,account`) — на бесконечной прокрутке
  отфильтровать на клиенте нельзя.
- `deletionRequested` ведёт в профиль → «Вход и безопасность» (как `emailChanged`), а не на
  `AccountDeletionScheduled`: этот экран для гостя и требует пароль из входа; адрес push на
  сервере поправлен так же.
- Предложение push — первая строка ленты (K4), а не плашка после первой закладки: показывается,
  пока push на устройстве не включён (в т. ч. «устарел» и «запрещён»), на инстансе есть ключи и
  не нажато «Не сейчас» (`localStorage`).
- Вкладка настроек «Уведомления» скрыта, если на инстансе нет VAPID-ключей (весь её контент —
  push).
- Опрос счётчика — с `SILENT_ERROR_META`: фоновый сбой раз в минуту не должен сыпать
  уведомлениями об ошибке.
- Сервис-воркер активируется сразу (`skipWaiting`), без `registerType: 'prompt'` и без тоста
  «доступно обновление»: кэша нет, обновление ничего не ломает. Prompt вернётся с precache в Фазе 4.
- Правило «не показывать push при видимой вкладке» не действует на iOS (открытый вопрос 1 решён).
- Не сделано: при больше 5 вкладках сервер закрывает самый старый поток, а `EventSource` в нём
  переподключается сам и по кругу вытесняет соседей — лимит почти недостижим, но если
  понадобится, закрытие потока должно отдавать клиенту «не переподключайся».
- Вид в браузере, SSE и push на реальном устройстве вручную не проверялись.

## Открытые вопросы

1. ~~**iOS и «тихий» push.**~~ Решено: на iOS push показывается всегда, правило «вкладка видима» — только вне iOS.
   Было: WebKit требует показать уведомление на каждый push, иначе отзывает
   подписку. Правило «при видимой вкладке не показывать» придётся ограничить не-WebKit браузерами (или на
   iOS показывать всегда). Решить при реализации SW.
2. ~~**Инвайты: кому.**~~ Решено: только создателю инвайта (`invites.createdBy`).
3. ~~**Сводка вместо россыпи пушей.**~~ Решено: больше 3 новых записей за проход крона — один push
   «Новые главы в N тайтлах» (`NEW_CHAPTERS_PUSH_LIMIT`).
4. ~~**Куда ведут `emailChanged` и `newDeviceLogin`.**~~ Решено: `/profile?tab=signInAndSecurity`.
5. ~~**Формат бейджа и точка закладок**~~ Решено: точка 8 px (B2), независима от точки закладок.
6. **Несколько реплик API.** Хаб SSE в памяти процесса работает при одной реплике. Если API
   масштабируется, рассылку надо переводить на pub/sub в Valkey; для текущего деплоя достаточно
   одного процесса. Подтвердить.

## Отвергнутые идеи

- **Письма-дайджесты о новых главах** — почта остаётся для системных писем.
- **Telegram-бот** — в роадмапе «После релиза», нужен привязочный флоу.
- **Одно уведомление на каждую главу или на каждый проход крона** — засоряет ленту и push на длинных
  тайтлах; выбран один тайтл — одна запись со счётчиком.
- **Хранить прочитанные (`readAt`) и дать их показать** — решено: прочитанное исчезает сразу.
- **Прочитанность через открытие ленты** — человек теряет, что именно было новым.
- **Бейдж колокольчика вместо точки закладок** — точка остаётся независимой.
- **Поповер у колокольчика на десктопе** — два вида одного и того же.
- **Только опрос счётчика** — отставание до минуты неприемлемо для безопасности и источников; опрос
  оставлен лишь запасным каналом.
- **Тост на каждое уведомление** — пачка новых глав после прохода крона завалила бы экран.
- **Офлайн-кэш ленты в Dexie** — потом, вместе с PWA Фазы 4.
- **Возможность отключить ленту «Аккаунт»** — безопасность не должна пропадать; отключается только push.
- **Отдельный счётчик ошибок `PARSER_FAILED` для админов** — `PARSER_FAILED` это код ошибки API, а не
  событие; «упавший парсер» определяется переходом источника в `down`.
